# Архитектура системы Multi-Agent (Crews v2)

## Обзор

Многопроцессная система является ядром openclaw-for-business, определённым в `crews/` в корневом каталоге проекта.

Ключевая идея: **разделение Template → Instance**. `crews/` содержит чертежи Crew, которые HRBP превращает в запущенные агенты. Один шаблон может быть инстанцирован в несколько экземпляров Crew.

Цели проектирования:
1. **Специализация задач** — каждый Crew фокусируется на определённой области
2. **Множественное инстанцирование** — один шаблон роли может создавать несколько независимых экземпляров (напр., два агента по обслуживанию для двух продукт-лайн)
3. **Параллельная обработка** — распределение задач на подпроцессы через `sessions_spawn` OpenClaw

Применяется **гибридный режим маршрутизации**:
- **Режим A (единая точка входа)**: пользователь общается с Main Agent через Feishu Bot, Main Agent распределяет задачи под-агентам через `sessions_spawn`
- **Режим B (прямой канал)**: под-агенты привязываются напрямую к определенным каналам через нативную `bindings` OpenClaw
- Один и тот же под-агент может использоваться одновременно обоими способами

## Основные концепции

### Template (шаблон)
Шаблон — это **чертёж** Crew, определяющий возможности, характер, инструменты и workflow. Хранится в каталоге `crews/`.

Источники шаблонов:
- **Встроенные** (built-in): main / hrbp / it-engineer — системные, автоматически устанавливаются через `setup-crew.sh`
- **Официальные** (official): customer-service / developer / content-writer / market-analyst / operations
- **Созданные пользователем** (user-created): создаются через HRBP
- **Из маркетплейса** (marketplace): future загрузка из маркетплейса Crew

### Instance (экземпляр)
Экземпляр — это **запущенная форма** шаблона — реальный рабочий агент. Особенности:
- Уникальный ID (напр., `cs-product-a`)
- Независимая рабочая область (`~/.openclaw/workspace-<instance-id>/`)
- Независимая память (MEMORY.md развивается независимо при работе)
- Независимая привязка канала

### Built-in Crew (встроенные Crew)
Три системных Crew, глобально уникальны, не могут быть удалены или инстанцированы несколько раз:

| ID | Роль | Особенности |
|----|------|-------------|
| `main` | Маршрутизатор + исполнитель при ошибке | Входное окно для сообщений |
| `hrbp` | Управление жизненным циклом Crew | Набор/переброс/увольнение |
| `it-engineer` | Системный администратор OFB | Установка/обновление/устранение неполадок |

## Архитектура

```
Режим A: Пользователь Feishu → Bridge → Gateway → Main Agent → spawn под-агент
Режим B: Пользователь канала → OpenClaw channel → Gateway bindings → Под-агент (прямой ответ)
```

**Тип процесса**: Gateway один процесс, все агенты запускаются внутренне как подпроцессы (логическая изоляция).

### Двухуровневая система навыков

Выравнивается с родной иерархией загрузки навыков OpenClaw:

| Уровень | Расположение | Путь установки | Область видимости |
|---------|-------------|---------------|------------------|
| Глобально общий | `skills/` (корень проекта) | `openclaw/skills/` | Все агенты |
| Специфичный для шаблона | `crews/<template>/skills/` | `~/.openclaw/workspace-<instance>/skills/` | Только этот экземпляр |

Стратегия по умолчанию (OFB):
- Каждый агент использует фиксированный базовый набор bundled навыков:
  `1password`、`healthcheck`、`model-usage`、`nano-pdf`、`skill-creator`、`ordercli`、`session-logs`、`tmux`、`weather`、`xurl`、`video-frames`
- Глобальные навыки, установленные в корневом `skills/` addon по умолчанию открыты для всех агентов
- `crews/<template>/skills/` addon устанавливается только в рабочую область этого экземпляра, не открывается другим агентам
- `BUILTIN_SKILLS` используется для добавления дополнительных bundled навыков поверх базового (напр., `github` / `gh-issues` / `coding-agent`)
- `DENIED_SKILLS` как финальный уровень отсечения (удаление из «база + добавление» указанных навыков)

## Основные компоненты

### Main Agent (маршрутизатор/диспетчер)
- Получение сообщений пользователя, определение намерения
- Приоритетно рассылка соответствующим под-агентам через `sessions_spawn`
- Сообщение о результатах под-агента
- Обработка только при отсутствии подходящего crew
- Если не найдён и намёк на недостающую способность — предложение набрать через HRBP

### HRBP Agent (управление жизненным циклом Crew)
- Управление библиотекой шаблонов Crew (просмотр, создание новых шаблонов)
- Полный жизненный цикл экземпляров: набор (инстанцирование), переброс (изменение), увольнение (архивирование)
- Защищен, не может быть удалён
- Пять навыков: `hrbp-recruit`、`hrbp-modify`、`hrbp-remove`、`hrbp-list`、`hrbp-usage`

### IT Engineer Agent (системное обслуживание)
- Ответственен за развертывание, обслуживание, обновление и устранение неполадок системы OFB
- Обращение к нетехническим пользователям простым языком
- Защищен, не может быть удалён

## Источники экземпляров

Crew экземпляры создаются тремя способами:

1. **Автоматическая установка встроенного**: `crews/main/`、`crews/hrbp/`、`crews/it-engineer/` — автоматически инстанцируются через `setup-crew.sh`, не управляются HRBP
2. **Инстанцирование HRBP**: пользователь через диалог с HRBP выбирает шаблон из библиотеки и инстанцирует в запущенный агент (стандартный способ)
3. **Привлечение addon-шаблона**: сторонние addon поставляют шаблоны через каталог `crew/`, устанавливаются `apply-addons.sh` в библиотеку шаблонов, затем HRBP инстанцирует (или addon указывает auto-activate)

## Структура рабочей области

Каждый workspace шаблона/экземпляра содержит 8 ключевых файлов:

| Файл | Назначение |
|------|-----------|
| SOUL.md | Позиция роли, граница идентичности |
| AGENTS.md | Workflow и процедуры |
| MEMORY.md | Долгосрочная память и контекст |
| USER.md | Предпочтения пользователя |
| IDENTITY.md | Имя, характер, голос |
| TOOLS.md | Доступные инструменты и правила использования |
| HEARTBEAT.md | Состояние здоровья |

Опциональные файлы:
- `DENIED_SKILLS` — список блокируемых встроенных навыков
- `BUILTIN_SKILLS` — дополнительные bundled навыки поверх базы OFB
- `skills/` — каталог специфичных для шаблона/экземпляра навыков

## Конфигурация

Конфигурация экземпляра агента в `~/.openclaw/openclaw.json` (только нативные поля верхнего уровня):

- `agents.list[]` — список экземпляров (id、name、workspace、subagents)
- `agents.list[].skills` — белый список навыков экземпляра (всегда записывается: база + добавление - denied + workspace-навыки)
- `bindings[]` — привязка канала (режим B прямой)
- `TEAM_DIRECTORY.md` — реальная адресная книга на основе `agents.list[]` + `bindings[]`

Связь шаблон-экземпляр поддерживается в MEMORY.md HRBP, не проникает в openclaw.json.

## Режимы маршрутизации

| Режим | Описание | Конфигурация |
|-------|----------|-------------|
| Spawn | Маршрутизация через Main Agent | Список `allowAgents` |
| Binding | Прямой канал | Элемент `bindings[]` |
| Both | Оба способа | Одновременная конфигурация |

Принудительная маршрутная запись:
- `[Route: @it-engineer] Посмотрите системные логи`
- `@it-engineer Посмотрите системные логи`

Привилегии жизненного цикла:
- Только `hrbp` может выполнять recruit/modify/remove
- `main` только идентифицирует и маршрутизирует в `hrbp`

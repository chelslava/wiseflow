# Как использовать после развертывания (рекомендуемый подход)

### Рекомендуемый трёхшаговый подход

Следующие три сценария представляют собой наиболее типичные процессы первоначальной настройки, можно копировать содержимое диалогов прямо как есть.

---

#### Шаг 1: Набор внутреннего Crew с помощью Main Agent (на примере «редактора новостной рассылки»)

> Тип crew: **internal** (действия выполняются в канале Main Agent)

**1.1 Набор редактора новостной рассылки**

```text
Вы (в канале main):
Наберите мне редактора новостной рассылки, используя шаблон selfmedia-operator, идентификатор — selfmedia-operator

# Main Agent покажет предложение по набору, ожидайте подтверждения
Вы: Подтверждаю

# Main Agent завершит инстанцирование и предложит перезапустить Gateway
```

**1.2 Внедрение бизнес-контекста в редактора**

После завершения инстанцирования и перезапуска Gateway сообщите Main Agent о внедрении контекста редактору (или после привязки отдельного канала редактору — диалог с ним напрямую):

```text
Вы:
Внедрите следующий контекст в долговременную память редактора новостной рассылки:
- Компания: <название вашей компании>, занимается <одним предложением о бизнесе>
- Платформы: WeChat Official Account <номер аккаунта> + Xiaohongshu
- Целевая аудитория: <описание типичной аудитории>
- Стиль аккаунта: <определение стиля, например, «технический, но одновременно живой и энергичный»>
- Темп публикации: 2 статьи в неделю — во вторник и пятницу
- Запрещённые темы: <неразрешённые конкуренты или темы>
- Крайне важно: <крайне важное примечание>

# Main Agent обновит MEMORY.md и USER.md для selfmedia-operator
```

**1.3 Начало работы**

```text
Вы (в канале main, прямая маршрутизация):
@selfmedia-operator Напишите статью на тему <тема> для <целевой аудитории>

# Либо привяжите отдельный канал для редактора и общайтесь напрямую
```

---

#### Шаг 2: Набор внешнего Crew с помощью HRBP (на примере продавца-консультанта)

> Тип crew: **external** (действия выполняются в канале HRBP)

**2.1 Сообщите HRBP о вашем бизнес-контексте и потребностях**

```text
Вы (в канале hrbp):
Мне требуется набрать продавца-консультанта в WeChat, на основе шаблона sales-cs.
Бизнес-контекст следующий:
- Компания: <название вашей компании>
- Продукт: <основной продукт/услуга>, <одним предложением о том, какая проблема решается для клиента>
- Уровни оплаты: <например, бесплатная пробная версия → VIP-подписка → корпоративная подписка>
- Внешнее обращение консультанта: <например, «помощник Сяо Мин»>
- Ответственный менеджер WeChat: <ID менеджера WeChat> (для сложных вопросов клиентов — переход на человеческий менеджер)
- Канал привязки: Feishu, ID аккаунта <channel_account_id>
```

**2.2 HRBP готовит инстанцирование и просит вас заполнить бизнес-форму**

```text
# HRBP покажет предложение по инстанцированию, ожидайте подтверждения
Вы: Подтверждаю

# HRBP завершит инстанцирование и предложит вам заполнить следующие поля в руководстве для консультанта:
# — FAQ по продукту (ответы на распространённые вопросы)
# — Ссылки на способ оплаты и покупки
# — Ссылка на анкету обратной связи
# — Ссылка на заявку на выставление счёта

Вы:
Вот частые вопросы по продукту:
Вопрос: <вопрос 1>? Ответ: <ответ 1>
Вопрос: <вопрос 2>? Ответ: <ответ 2>
Ссылка на покупку: <ссылка>
Анкета обратной связи: <ссылка>
Заявка на выставление счёта: <ссылка>

# HRBP сохранит эти данные в MEMORY.md экземпляра sales-cs
```

**Важно: внешние crew обязательно должны привязываться к отдельному каналу для обслуживания внешних клиентов, рекомендуется использовать расширение awada из этого репозитория**

**2.3 Перезапуск Gateway, продавец-консультант выходит на связь**

```text
Вы: Подтверждаю, перезапустите Gateway

# Или вручную в терминале:
# ./scripts/dev.sh gateway
```

#### Шаг 3: Ежедневное обслуживание с помощью IT Engineer

> IT Engineer — встроенный системный crew, не требует набора, доступен через маршрутизацию в канале Main Agent

**3.1 Инспекция системы**

```text
Вы (в канале main):
@it-engineer Выполните инспекцию системы, проверьте особенно:
- Работоспособность конфигурации модели/API
- Статус привязки каналов для разных crew
- Были ли в последнее время аномальные логи
```

**3.2 Обновление системы**

```text
Вы: @it-engineer Обновите систему до последней версии

# IT Engineer выполнит ./scripts/install.sh и сообщит результат
```

**3.3 Устранение неполадок**

```text
Вы:
@it-engineer Редактор новостной рассылки сегодня сообщил, что сбой при вызове инструментов, выясните причину

# IT Engineer проверит логи, конфигурацию, локализует проблему и устранит её
```

**3.4 Просмотр адресной книги команды**

```text
Вы: Подскажите, какие crew сейчас находятся в команде, и каков статус их привязки

# Main Agent прочитает TEAM_DIRECTORY.md и выведет текущее состояние команды
```

#### Шпаргалка: быстрый старт за 3 минуты (можно копировать прямо)

```text
# Набор внутреннего crew (в канале main)
Вы: Наберите мне редактора новостной рассылки, используя шаблон selfmedia-operator

# Внедрение бизнес-контекста (в канале main)
Вы: Внедрите следующий контекст в редактора новостной рассылки: [бизнес-контекст...]

# Набор внешнего crew (в канале hrbp)
Вы: Мне требуется набрать продавца-консультанта в WeChat, на основе шаблона sales-cs, [бизнес-контекст...]

# Инспекция системы (маршрутизация в канале main)
Вы: @it-engineer Выполните инспекцию системы

# Просмотр статуса команды
Вы: Подскажите, какие crew сейчас работают
```

# Производственное развёртывание

```bash
# Однократная установка в виде системного демона (автоматическая загрузка последней версии кода + сборка + автозапуск при старте + перезапуск при сбое)
./scripts/install.sh
```

Для дальнейших обновлений выполняйте ту же команду:

```bash
./scripts/install.sh
```

> `install.sh` является идемпотентной операцией — при повторном выполнении обновляются только изменившиеся части, пользовательские данные не перезаписываются.

> **Синхронизация с собственным форком**: если вы создали форк этого проекта и внесли в него кастомные изменения, сначала убедитесь, что `origin` указывает на ваш форк, `install.sh` по умолчанию берёт код из origin.

## Часто используемые команды

```bash
./scripts/dev.sh gateway              # Запуск в режиме разработки
./scripts/dev.sh gateway --port 18789 # Указать порт
./scripts/install.sh                  # Производственное развёртывание / обновление (идемпотентно)
./scripts/install.sh --skip-crew      # Только переустановить демон, пропустить синхронизацию crew
./scripts/apply-addons.sh             # Применить addon-ы повторно (patches + skills + crew)
./scripts/setup-crew.sh               # Переустановить конфигурацию системы агентов
./scripts/setup-crew.sh --force       # Переопределить существующую рабочую область
```

# Руководство по разработке Addon

В этом руководстве объясняется, как разрабатывать addons для **wiseflow**.

Addon — это отдельный репозиторий Git, устанавливаемый в директорию `addons/`. Он может расширять wiseflow двумя способами, применяемыми в этом порядке `scripts/apply-addons.sh`:

1. **`skills/`** — глобальные навыки, видимые всем агентам
2. **`crew/`** — шаблоны Crew, устанавливаемые в `crews/` и управляемые HRBP

> **Примечание:** Addons **не** поддерживают патчи или перекрытия зависимостей. Если требуется патчинг исходного кода `openclaw/`, разместите файл патча в директории `patches/` на уровне проекта (только для сопровождающих ядра wiseflow). Это сохраняет интерфейс addon простым и стабильным при обновлениях upstream openclaw.

---

## Структура папок Addon

```
<addon-name>/
├── addon.json              # Обязательно: метаданные addon
├── skills/
│   └── <skill-name>/
│       ├── SKILL.md        # Определение навыка (обязательно)
│       └── scripts/        # Сопровождающие скрипты (опционально)
└── crew/
    └── <template-id>/
        ├── SOUL.md         # Обязательно — определение роли (должен объявлять command-tier)
        ├── AGENTS.md       # Workflow и процедуры
        ├── MEMORY.md       # Начальная память / бизнес-контекст
        ├── USER.md         | Предположения о пользователе
        ├── IDENTITY.md     # Имя и персона
        ├── TOOLS.md        # Руководство по инструментам
        ├── HEARTBEAT.md    # Шаблон проверки здоровья
        ├── BOOTSTRAP.md    # Введение в онбординг (показывается только при первом запуске)
        ├── DENIED_SKILLS   # Опционально: встроенные навыки для блокировки
        └── skills/
            └── <skill-name>/   # Навыки, ограниченные шаблоном (видны только этому crew)
                └── SKILL.md
```

## Формат `addon.json`

```jsonc
{
  "name": "my-addon",
  "version": "1.0.0",
  "description": "Что делает этот addon",
  "openclaw_version": "2026.4.11",        // опционально: объявление совместимости openclaw
  "openclaw_commit": "<commit-sha>",      // опционально: закрепление на точном коммите
  "internal_crews": ["my-ops-bot"],       // шаблоны crew, которые являются внутренними (управляются Main Agent)
  "external_crews": ["my-customer-bot"],  // шаблоны crew, которые являются внешними (управляются HRBP)
  "auto-activate": false                  // установите true для автоматического инстанцирования шаблонов crew при применении
}
```

### Объявление типа Crew

Массивы `internal_crews` и `external_crews` в `addon.json` являются **единственным авторитетом** для присвоения типа crew:

- Шаблоны, перечисленные в `internal_crews` → **внутренние** (наследует все глобальные навыки, жизненным циклом управляется Main Agent)
- Шаблоны, перечисленные в `external_crews` → **внешние** (использует только DECLARED_SKILLS, жизненным циклом управляется HRBP)
- Шаблоны, не перечисленные в массивах → по умолчанию **внешние** с предупреждением
- Шаблон, перечисленный в **обоих** массивах → ошибка, `apply-addons.sh` будет прерван

Поле `crew-type:` в `SOUL.md` **не требуется** для addon шаблонов. Если присутствует, будет перезаписано `apply-addons.sh` для соответствия объявлению в `addon.json`.

## Слой 1 — Глобальные навыки (`skills/`)

Навыки, размещённые здесь, устанавливаются в `openclaw/skills/` и делаются доступными всем агентам.
Каждый навык требует файла `SKILL.md` в корне навыка.

Глобальные навыки перечисляются в `~/.openclaw/GLOBAL_SHARED_SKILLS` после запуска `apply-addons.sh`.

---

## Слой 2 — Шаблоны Crew (`crew/`)

### Обязательно: Объявление уровня команд

Каждый шаблон crew **должен** объявлять уровень команд в `SOUL.md`. `setup-crew.sh` считывает это объявление и автоматически генерирует:
1. `agents.list[].tools.exec` в `openclaw.json` (политика безопасности/запроса на основе агентов)
2. Записи `~/.openclaw/exec-approvals.json` (белые списки команд на основе агентов с разрешёнными бинарными путями)

Добавьте этот раздел в `SOUL.md` (до или после `## Стиль общения`):

```markdown
## Уровень привилегий
command-tier: T1
```

**Четыре уровня** (полные списки команд см. в `crews/shared/COMMAND_TIERS.md`):

| Уровень | Имя | Политика выполнения | Типичный тип Crew |
|---------|-----|---------------------|-------------------|
| `T0` | read-only | `security: deny` — без выполнения shell | Customer service, content creation, research |
| `T1` | basic-shell | `security: allowlist` — только чтение: `cat`, `ls`, `grep`, `ps`, `curl` (только GET) | Coordination, operations |
| `T2` | dev-tools | `security: allowlist` — T1 + `git`, `npm`, `pnpm`, `node`, `python`, `cp`, `mv`, `mkdir`, `rm`, ... | Development, automation |
| `T3` | admin | `security: full` — неограниченный доступ к shell | Infrastructure, sysops |

Выберите **минимальный уровень**, необходимый для роли. Если есть сомнения — выбирайте более низкий уровень — HRBP или пользователь могут предоставить дополнительные привилегии после развёртывания.

### Тонкая настройка с помощью `ALLOWED_COMMANDS`

Чтобы добавить или удалить команды относительно базового уровня, создайте файл `ALLOWED_COMMANDS` в директории шаблона:

```
# Префикс + для разрешения, - для запрета
+./scripts/setup-crew.sh
-rm
```

Эти корректировки применяются поверх базового белого списка уровня и автоматически отражаются в `exec-approvals.json`.

### Поведение навыков по типу Crew

**Внутренние crews** (`internal_crews`):
- Наследуют **все глобальные навыки** — каждый навык, установленный в `openclaw/skills/` (как встроенный, так и предоставленный addon), виден по умолчанию
- Используйте `DENIED_SKILLS` для исключения конкретных навыков, к которым crew не должен иметь доступ
- Файл `BUILTIN_SKILLS` по-прежнему поддерживается для обратной совместимости, но редко нужен, так как по умолчанию уже "всё"

**Внешние crews** (`external_crews`):
- Используют **режим объявления** — видны только навыки, явно перечисленные в `DECLARED_SKILLS`
- `DECLARED_SKILLS` может ссылаться как на глобальные навыки (из `openclaw/skills/`), так и на навыки, ограниченные шаблоном (из `crew/<template>/skills/`)
- Навыки, ограниченные шаблоном, автоматически добавляются (не нужно их перечислять в `DECLARED_SKILLS`)
- Навык `self-improving` всегда блокируется для внешних crews

### Поведение инстанцирования

По умолчанию установленные шаблоны **не автоматически инстанцируются** — они становятся доступными в библиотеке HRBP/Main Agent, и пользователь может инстанцировать их по требованию.

Чтобы автоматически инстанцировать при `apply-addons.sh`, установите `"auto-activate": true` в `addon.json`. Это создаёт `workspace-<template-id>` и регистрирует агента немедленно. Используйте осторожно: идентификатор экземпляра будет равен идентификатору шаблона, существующие рабочие области будут пропущены (не перезаписаны).

### `DENIED_SKILLS` (только для внутренних crews)

Если ваш шаблон внутреннего crew не должен иметь доступа к определённым навыкам, перечислите их по одному на строку в `DENIED_SKILLS`:

```
github
gh-issues
coding-agent
```

### `DECLARED_SKILLS` (только для внешних crews)

Шаблоны внешних crews должны объявлять необходимые навыки в `DECLARED_SKILLS`:

```
customer-db
smart-search
rss-reader
```

## Тестирование вашего Addon локально

1. Склонируйте ваш addon в `addons/<addon-name>/`
2. Запустите `./scripts/apply-addons.sh` — он полностью идемпотентен
3. Перезапустите gateway: `./scripts/dev.sh gateway`
4. Для шаблонов crew: попросите HRBP инстанцировать новый шаблон

Чтобы принудительно повторно применить (напр., после обновления шаблона crew, уже существующего в `crews/`):

```bash
./scripts/apply-addons.sh --force
```

---

## Совместимость при обновлении

При изменении версии upstream `openclaw`:

- **`skills/`** — редко затрагивается, если не изменился API навыков openclaw
- **Шаблоны `crew/`** — обновите, если `SOUL.md` ссылается на поведение upstream, которое изменилось

Проверьте `openclaw.version` для закрепления коммита upstream. При подаче вашего addon в сообщество документируйте, какие диапазоны версий wiseflow он поддерживает.

# Инструкции в инъекции — Примечание к инъекциям

В этом документе описывается содержание всех инструкций, автоматически вводимых скриптами в workspace агента, для удобства отслеживания и устранения неполадок.

---

## Механизм инъекции

Инъекция инициируется двумя скриптами, оба идемпотентны (сначала проверяется наличие маркерных строк):

| Сценарий инициации | Скрипт | Цель инъекции |
|-------------------|--------|---------------|
| Первичная установка/синхронизация встроенных Crew | `scripts/setup-crew.sh` | `~/.openclaw/workspace-{main,hrbp,it-engineer}/TOOLS.md` |
| Новая регистрация Crew (HRBP recruitment / Main Agent recruitment для внутренних crew) | `crews/hrbp/skills/hrbp-recruit/scripts/add-agent.sh` | `~/.openclaw/workspace-{agentId}/TOOLS.md` |

Реализация функции инъекции:
- `scripts/lib/agent-skills.sh` → `inject_file_edit_guide()` (для использования в `setup-crew.sh`)
- `crews/hrbp/skills/hrbp-common/scripts/lib.sh` → `inject_file_edit_guide()` (для использования в `add-agent.sh`)

Маркер идемпотентности: `## 本地文件操作规范` (первичное обнаружение, пропустить, если уже присутствует)

---

## Содержание инъекции (добавляется в конец TOOLS.md)

```markdown
## 本地文件操作规范

1. **Предпочтение малых изменений**: сначала прочитайте актуальное содержимое файла, скопируйте точный отрезок оригинала, а затем используйте edit
2. **Крупные изменения — напрямую**: полный перезапись через write (сначала на основе актуального содержимого)
3. **Избегать слишком больших изменений за раз**: разбивайте на несколько небольших патчей, чтобы уменьшить несоответствия
4. **Точное основание — read результат**: не полагайтесь на отрендеренный текст в чате (напр., форматы имен файлов со ссылками), используйте результат инструмента read

## Спецификация sessions_spawn

> ⚠️ **Запрещена передача параметра `streamTo`** — `streamTo` поддерживает только `runtime=acp`, в режиме subagent вызывает ошибку (`streamTo is only supported for runtime=acp`). При spawn передавайте только agentId и содержимое задачи。
```

---

## Позиция инъекции: TOOLS.md (не AGENTS.md)

**Причина выбора TOOLS.md**:

- Действия по работе с локальными файлами (read/edit/write) и `sessions_spawn` относятся к **правилам вызова инструментов**
- AGENTS.md фиксирует workflow и бизнес-протоколы (напр., Technical Issue Dispatch Protocol), а не правила работы с инструментами

**Разделение обязанностей**:

| Файл | Расположение контента |
|------|----------------------|
| `SOUL.md` | Идентичность, роль, основные принципы, уровень автономии |
| `AGENTS.md` | Workflow, протоколы маршрутизации, бизнес-правила (включая Technical Issue Dispatch Protocol) |
| `TOOLS.md` | Список инструментов + правила вызова инструментов (включая общие инъекционные правила) |

---

## Граничное состояние между заранее определённым и инъекционным контентом

Следующие правила **не должны** быть прописаны в шаблонном TOOLS.md (предоставляются инъекцией):

- Предупреждение о запрете передачи `streamTo`
- Правила по работе с файлами («сначала прочитай, потом поменяй», «прочитай актуальное содержимое»)

Следующие правила **всё ещё находятся** в ручном TOOLS.md шаблона (специфичны для агента, не могут быть перезаписаны инъекцией):

- Специфичные ограничения `sessions_spawn` (напр., main не может spawn hrbp, внешние crew не могут spawn)
- Способ использования специфичных инструментов (напр., crew lifecycle scripts hrbp, системные команды it-engineer)

Следующий контент **только в AGENTS.md**, не в TOOLS.md:

- **Technical Issue Dispatch Protocol** (специфичен для встроенных Crew, описывает workflow вызова IT Engineer при возникновении технических сбоев)

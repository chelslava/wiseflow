# PPT Maker

Генерация профессиональной `.pptx` презентации из содержимого рукописи. Поддержка:

- **Извлечение стиля шаблона**: загрузка эталонного PPTX или снимка экрана для автоматического извлечения цвета и макета
- **AI-иллюстрации**: генерация обложки и иллюстраций содержимых страниц через `siliconflow-img-gen` (замена API Google/ChatGPT)
- **Библиотека материалов**: расширяемое подключение pexels-footage / pixabay-footage для получения изображений без отчислений
- **Чистая Python генерация**: JSON → python-pptx, без Node.js или внешних API (кроме генерации изображений)

## Зависимости

```bash
pip install python-pptx
```

Этот скрипт зависит от `python-pptx`. Если не установлен, скрипт вернет команду установки.

## Рабочий процесс

```
Пользователь предоставляет рукопись + необязательный шаблон
         │
         ▼
 ┌───────────────────┐
 │ Шаг 1: Анализ стиля │  ← При наличии PPTX шаблона: запустите команду extract для извлечения темы
 │                   │  ← При наличии эталонного снимка: LLM анализирует цвет/макет
 │                   │  ← При отсутствии шаблона: используйте тему по умолчанию или подтвердите стиль с пользователем
 └────────┬──────────┘
          │
          ▼
 ┌───────────────────┐
 │ Шаг 2: Генерация структуры │  ← LLM анализирует структуру рукописи, планирует контент и макет каждой страницы
 │                   │  ← Определите, какие страницы требуют иллюстраций
 └────────┬──────────┘
          │
          ▼
 ┌───────────────────┐
 │ Шаг 3: Подготовка иллюстраций │  ← AI изображение: siliconflow-img-gen (обложка 16:9/иллюстрации содержимых страниц)
 │                   │  ← Материалы: pexels-footage / pixabay-footage (необязательно)
 │                   │  ← Пользователь изображения: непосредственно ссылка на пути к изображениям из пользователя
 └────────┬──────────┘
          │
          ▼
 ┌───────────────────┐
 │ Шаг 4: Генерация PPTX │  ← Сборка JSON конфигурации, запуск generate_pptx.py
 │                   │  ← Вывод .pptx файла
 └────────┬──────────┘
          │
          ▼
 ┌───────────────────────┐
 │ Шаг 5: Визуальная проверка │  ← Постраничное преобразование в PNG, просмотр макета моделью визуального ИИ
 │  (обязательно для выполнения)│  ← Проверка размера шрифта, смещения макета, наложения элементов и т.д.
 │                       │  ← Обнаружение проблем → исправление JSON → повторная генерация → повторная проверка
 └────────┬──────────────┘
          │
          ▼
     Доставка PPTX файла
```

### Шаг 1: Анализ стиля

#### 1a. Пользователь предоставил шаблон PPTX

```bash
python3 {baseDir}/scripts/generate_pptx.py \
  --extract-style \
  --template /path/to/template.pptx
```

Выводит тему шаблона (цвет, шрифт, макет). Сопоставьте извлеченные цвета с полем `theme` конфигурации JSON.

Если `python-pptx` не установлен, скрипт вернет error и предложит установку или использование режима анализа LLM (см. 1c).

#### 1b. Пользователь предоставил эталонное изображение

Анализ изображения стиля LLM, извлечение:

```json
{
  "colors": {
    "primary": "#1E3A8A",
    "accent": "#E94560",
    "background": "#FFFFFF",
    "text": "#1F2937"
  },
  "layout": "Левый верхний заголовок + центральный контент",
  "typography": "Жирный заголовок 36px +正文 18px"
}
```

Сопоставьте извлеченные цвета с полем `theme` конфигурации JSON.

#### 1c. Отсутствие шаблона (тема по умолчанию)

Уточните у пользователя направление стиля:
- **Бизнес-профессиональный**: основной темно-синий цвет + белый фон (`primary_color: "1A3C6E"`)
- **Технологическая энергия**: глубокий морской синий + электрический синий акцент (`primary_color: "0F172A"`, `accent_color: "38BDF8"`)
- **Минималистичный белый**: белый фон + одноцветный акцент (`primary_color: "1A1A1A"`, `background_color: "FFFFFF"`)
- Или пользовательская настройка

### Шаг 2: Генерация структуры

Анализ содержимого рукописи LLM, вывод структурного планирования для каждой страницы:

```
1. Обложка (cover)
   - Заголовок: {основной заголовок}
   - Подзаголовок: {подзаголовок}
   - Иллюстрация: AI генерация абстрактного технологического фона

2. Страница содержания (toc)
   - Разделы: {3-5 разделов}

3. Разделительные страницы (section)
   - "01 Обзор рынка"

4-N. Страницы содержимого (content / two_column / image_full)
   - Заголовок + пункты + позиция иллюстрации

N+1. Завершающая страница (ending)
```

Показать структуру пользователю для подтверждения перед продолжением.

### Шаг 3: Подготовка иллюстраций

#### Стратегия приоритетов

| Тип изображения |Preferred方案|备选方案|
|---------|---------|---------|
| Обложка | siliconflow-img-gen | Чистый цветной фон|
| Контцептуальная иллюстрация | siliconflow-img-gen | Материалы pexels/pixabay |
| Графика данных | Предоставляется пользователем | Материалы pexels/pixabay |
| Скриншот продукта | Предоставляется пользователем | — |
| Logo / QR-код | Предоставляется пользователем | — |

#### Использование siliconflow-img-gen для генерации иллюстраций

```bash
# Обложка (16:9)
python3 {baseDir}/../siliconflow-img-gen/scripts/gen.py \
  --prompt "абстрактный технологический фон, {тематическое описание}, {основной цвет} градиент, современно и просто, подходит для обложки PPT, горизонтальный баннер 16:9" \
  --image-size 1664x928 \
  --out-dir ./tmp/ppt-images

# Иллюстрации содержимых страниц (16:9)
python3 {baseDir}/../siliconflow-img-gen/scripts/gen.py \
  --prompt "{тема страницы} концептуальная иллюстрация, плоский дизайн, {основной цвет}, просто и профессионально" \
  --image-size 1664x928 \
  --out-dir ./tmp/ppt-images
```

**Обязательная проверка после генерации**: Проверьте, что изображение не является одноцветной белой доской (偶发异常 siliconflow), при аномалии повторите (не более 3 раз).

#### Использование библиотеки материалов (необязательно, интеграция в будущем)

```
# pexels-footage (в разработке)
python3 {baseDir}/../pexels-footage/scripts/search.py --query "бизнес-встреча" --orientation landscape

# pixabay-footage (в разработке)
python3 {baseDir}/../pixabay-footage/scripts/search.py --query "технология абстракция" --orientation horizontal
```

### Шаг 4: Генерация PPTX

#### Сборка JSON конфигурации

Смотрите `references/slide-layouts.md` чтобы узнать формат JSON каждого типа слайда.

Соберите тему Шага 1, структуру Шага 2 и пути к изображениям Шага 3 в полный JSON:

```json
{
  "theme": {
    "primary_color": "1A3C6E",
    "secondary_color": "16213E",
    "accent_color": "E94560",
    "background_color": "FFFFFF",
    "text_color": "333333",
    "heading_font": "Microsoft YaHei",
    "body_font": "Microsoft YaHei"
  },
  "slides": [
    {
      "type": "cover",
      "title": "Отчет о бизнесе за квартал",
      "subtitle": "Итоги работы Q1 2026",
      "author": "Отдел бизнес-развития",
      "background_image": "./tmp/ppt-images/00.png",
      "background_color": "1A3C6E"
    },
    {
      "type": "toc",
      "title": "Содержание",
      "items": ["Обзор рынка", "Ключевые достижения", "Проблемы и вызовы", "Планы на следующий квартал"]
    }
  ]
}
```

Запишите JSON в файл (например, `./tmp/slides-config.json`).

#### Запуск скрипта генерации

```bash
python3 {baseDir}/scripts/generate_pptx.py \
  --config ./tmp/slides-config.json \
  --output ./output/presentation.pptx

# При необходимости унаследовать мастер/макет из шаблона PPTX
python3 {baseDir}/scripts/generate_pptx.py \
  --config ./tmp/slides-config.json \
  --output ./output/presentation.pptx \
  --template /path/to/template.pptx
```

### Шаг 5: Визуальная проверка (обязательно для выполнения)

После генерации PPTX, **обязательно преобразовать каждую страницу в PNG изображения**, просмотрите макет с помощью визуальной модели. Это критически важный этап для автоматизированного процесса, гарантирующего качество макета.

#### 5a. Постраничное преобразование в PNG

```bash
python3 {baseDir}/scripts/pptx_to_png.py \
  --input ./output/presentation.pptx \
  --outdir ./tmp/ppt-pngs
```

Этот скрипт зависит от установленной в системе LibreOffice (`libreoffice-impress`). Если не установлен, скрипт выдаст подсказку об установке.

После преобразования в директории `./tmp/ppt-pngs/` будут сгенерированы `Slide1.png`, `Slide2.png`... по одному файлу на слайд.

#### 5b. Постраничный визуальный обзор

**Откройте каждое PNG изображение с помощью инструмента Read**, постранично проверьте следующие элементы:

| Пункт проверки | Пункт наблюдения | Критерий оценки |
|--------|--------|---------|
| **Общее смещение** | Смещены ли все содержимые элементы вверх/вниз/влево/вправо | Равномерные поля, содержимое по центру |
| **Размер шрифта** | Заголовок/тело слишком большие (переполнение) или слишком маленькие (нечитаемые) | Заголовок около 28-44pt,正文 около 16-20pt, визуально сбалансированное соотношение |
| **Обрезка текста** | Длинный текст переполняет границы слайда и обрезается | Текст полностью отображается, достаточные отступы |
| **Наложение элементов** | Текстовые рамки/изображения/декоративные линии взаимно перекрываются | Четкие границы между элементами, без перекрытия |
| **Качество изображения** | Иллюстрация отображается нормально, пропорции не искажены | Изображение четкое, правильное горизонтальное/вертикальное соотношение, без голых плейсхолдеров |
| **Читаемость цвета** | Достаточный контраст между текстом и фоном | Темный фон с светлым текстом или светлый фон с темным текстом, легко читаемый |
| **Единый стиль** | Единый стиль каждой страницы, профессиональный макет | Единообразный стиль, без резких различий |

**Процесс обзора**:

1. Откройте `Slide1.png` (обложку) с помощью инструмента Read, проверьте позицию заголовка, фоновое изображение, акцентную линию
2. Последовательно откройте все последующие PNG, постранично проверьте
3. Запишите для каждой страницы: `PASS` или `FAIL (причина: xxx)`
4. Только все страницы `PASS` могут перейти к этапу доставки

#### 5c. При обнаружении проблем

При `FAIL` любой страницы, следуйте следующему процессу исправления:

1. **Анализ корневой причины**: Определить, является ли проблема в конфигурации JSON (неправильные параметры размера шрифта/позиции) или в логике рендеринга скрипта
2. **Исправление JSON конфигурации**: Скорректируйте параметры конфигурации соответствующего слайда (размер шрифта, позиция, цвет и т.д.)
3. **Повторная генерация**: Запустите `generate_pptx.py` для повторной генерации .pptx
4. **Повторная проверка**: Повторите 5a → 5b, пока все страницы не пройдут проверку `PASS`
5. **Не более 3 циклов повтора**: При наличии проблем после 3 циклов, запишите конкретные проблемы и сообщите пользователю, нельзя бесконечно циклически повторять

#### 5d. Быстрый справочник по распространенным проблемам

| Феномен | Возможная причина | Метод исправления |
|------|---------|---------|
| Все содержимые элементы смещены вниз | Проблема с настройкой высоты слайда или смещение мастер-шаблона | Проверьте slide_height, или измените значение top всех элементов в JSON |
| Шрифт слишком большой, переполняет страницу | Слишком большой параметр размера шрифта | Уменьшите `font_size`, заголовок обложки не более 44,正文 не более 20 |
| Квадратные символы китайского текста | Шрифт не поддерживает китайский текст | Измените `heading_font`/`body_font` на `"Microsoft YaHei"` или `"SimHei"` |
| Изображение перекрывает текст | image_position конфликтует с фактической компоновкой | Используйте позицию `"bottom"` или уменьшите масштаб изображения |
| Список длинных элементов переполняет нижнюю часть | Слишком много пунктов bullet | Разделите на несколько страниц или уменьшите размер шрифта/межстрочный интервал |

### Шаг 6: Доставка

1. Подтвердите, что файл `.pptx` сгенерирован и все визуальные проверки прошли успешно
2. Сообщите пользователю путь к файлу, количество слайдов, используемый стиль
3. Очистите временные файлы (`./tmp/ppt-images/`, `./tmp/ppt-pngs/` и `./tmp/slides-config.json`), если пользователь не требует их сохранения

## Быстрый справочник по типам слайдов

| type | Назначение | Ключевые поля |
|------|------|---------|
| `cover` | Обложка | title, subtitle, author, background_image |
| `toc` | Содержание | title, items[] |
| `section` | Разделитель | number, title, subtitle |
| `content` | Стандартное содержимое | title, body, bullets[], image, image_position |
| `two_column` | Сравнение в две колонки | left_title, left_body[], right_title, right_body[] |
| `image_full` | Полная иллюстрация | image, title, caption |
| `ending` | Благодарственная страница | title, subtitle, contact, qr_image |

Детальный формат JSON и примеры см. в `references/slide-layouts.md`.

## Анимодель

- Не пропускать визуальную проверку (Шаг 5) после генерации PPTX, это самый распространенный источник проблем с качеством макета
- Не устанавливать переменные окружения в строке (SILICONFLOW_API_KEY=... python3 ...) при использовании `siliconflow-img-gen` для генерации изображений, API-ключ уже в системной среде
- Не пропускать шаг проверки (одноцветная белая доска) после генерации изображения
- JSON каждой страницы должен содержать поле `type`
- Значения цветов не должны содержать префикс `#` (требуется python-pptx)
- Используйте абсолютные пути или корректные относительные пути к изображениям относительно рабочей директории скрипта

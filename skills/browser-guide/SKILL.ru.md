# Рекомендации по использованию браузера

Соблюдайте эти правила при использовании инструмента `browser` для взаимодействия с веб-страницами.

## 1. Запросы на вход

Когда на странице появляется барьер входа, сначала определите предложенный механизм входа, затем следуйте соответствующей процедуре ниже.

**Общее ограничение: повторяйте попытку входа не более 2 раз за попытку — частые повторы рискованно для аккаунта.**

### 1-A. Учетные данные, сохраненные в браузере

1. Проверьте, были ли учетные данные пользователей автоматически заполнены в форме входа. Если да, используйте их.
2. При неудаче продолжайте по 1-B / 1-C / 1-D как следует.

### 1-B. Вход по QR-коду

Когда на странице входа отображается QR-код (бэкенд WeChat Official Account, центр создателей Xiaohongshu, X/Twitter и др.):

1. Используйте `snapshot` для нахождения элемента изображения QR-кода. Скачайте / сделайте скриншот и сохраните в `/tmp/` (например, `/tmp/xhs_qr.png`).
2. Отправьте изображение QR-кода из предыдущего шага пользователю сообщением, убедитесь, что отправляете само изображение, а не локальный путь к файлу.
3. Уведомите пользователя:
   > "Вход на **[название платформы]** стал недействителен (или используется впервые). Пожалуйста, просканируйте следующий QR-код с помощью приложения **[название платформы]** на вашем телефоне. После сканирования и нажатия подтверждения на телефоне, ответьте сообщением '扫码完成'."
4. **Остановитесь и дождитесь** сообщения пользователя "扫码完成", "ок", "закончил сканирование" или любой эквивалентной подтверждение перед продолжением.
5. В ожидании опрашивайте страницу каждые **3 секунды** с помощью `snapshot` на признаки успешного входа (изменение URL, исчезновение QR-кода, появление дашборда/аватара). Если автоопределение произошло, продолжайте немедленно, не дожидаясь ответа пользователя.
6. Если сканирование не происходит в течение **3 минут** и сообщения не поступает, отправьте: _"Время сканирования истекло, будет продолжена обработка текущего доступного контента."_ и продолжайте.

### 1-C. Вход по SMS-коду

Когда страница входа требует номер телефона и SMS-код подтверждения:

1. Спросите пользователя о зарегистрированном номере телефона для этой платформы:
   > "Для входа на **[название платформы]** требуется SMS-код. Пожалуйста, сообщите ваш номер телефона, на который зарегистрирован аккаунт."
2. После получения номера введите его и инициируйте запрос SMS-кода. Повторите попытку **не более 2 раз**, если первый запрос не удался.
3. Спросите пользователя о коде подтверждения:
   > "SMS-код отправлен. Пожалуйста, сообщите код подтверждения, который вы получили."
4. Введите код и завершите вход. При неудаче входа сообщите пользователю и продолжайте с доступным контентом — **не повторяйте третий раз**.

### 1-D. Вход по имени пользователя / паролю

Когда доступна только форма имени пользователя + пароль:

1. Сначала проверьте наличие учетных данных, сохраненных в браузере (см. 1-A).
2. Если нет, спросите пользователя о предпочтениях:
   > "Для входа на **[название платформы]** требуется姓名 пользователя и пароль. В браузере не найдены предварительно сохраненные пароли. Выберите: ① Вы можете войти самостоятельно в браузере и сообщить мне, ② Сообщите имя пользователя и пароль, и я выполню вход за вас."
3. Если пользователь выбирает ②, получите учетные данные и попробуйте войти. Повторяйте **не более 2 раз** при неудаче.
4. При неудаче после 2 попыток сообщите пользователю и продолжайте с доступным контентом.

### 1-E. Fallback — вход невозможен

Если вход по какой-либо причине не может быть завершен (тайм-аут, недоступность пользователя, повторные неудачи):

- **НЕ ОСТАНАВЛИВАЙТЕСЬ и не прерывайте задачу.**
- Продолжайте с любым доступным контентом в состоянии без входа.
- В конце включите примечание в результат: _"Примечание: вход на [название платформы] не удался, следующий контент получен из состояния без входа и может быть неполным."_

## 2. Простая проверка / капча

Когда на странице появляется однокликовая проверка (например, кнопка с ярлыком "去验证", "Verify", "Я не робот", или простой флажок):

1. Попробуйте нажать кнопку/флажок проверки напрямую.
2. Подождите несколько секунд для обновления страницы.
3. Сделайте snapshot и проверьте, загрузился ли обычный контент.
4. Если страница теперь показывает ожидаемый контент, продолжайте задачу.

## 3. Fallback для сложной проверки

Если простое нажатие на шаге 2 выше **не удалось** — страница по-прежнему показывает задачу, задача представляет собой пазл/слайдер/выбор изображения CAPTCHA, или произошла ошибка:

1. **НЕ пытайтесь повторить слепо.** Остановите автоматизированную проверку.
2. Отправьте сообщение пользователю: _"На странице xx есть капча, я не могу решить. Пожалуйста, завершите проверку в браузере, после завершения сообщите мне."_ (xx — название страницы).
3. Дождитесь подтверждения пользователя.
4. Если ответ не придет в течение **5 минут**, продолжайте с любым доступным контентом.

## 4. Контент с ленивой загрузкой

Когда страница использует ленивую загрузку (бесконечная прокрутка, секции "загрузить больше", контент появляется только после прокрутки):

1. Перед прокруткой оцените, является ли до-загруженный контент **релевантным** для текущей задачи.
2. Если релевантно, имитируйте человеческую прокрутку: прокручивайте постепенно вниз, коротко останавливайтесь между прокрутками для загрузки контента, затем сделайте snapshot для захвата нового контента.
3. Повторяйте, пока нужный контент не станет видимым или более новый контент не загрузится.
4. Не прокручивайте слишком быстро, делайте это как человек. После 7 прокруток вы должны остановить этот этап.
5. Если не релевантно, пропустите прокрутку и работайте с уже загруженным контентом.

## 5. Подписные барьеры

Когда страница указывает, что контент за подписным барьером или требует конкретной подписки (например, "Подпишитесь, чтобы продолжить чтение", "Продолжите чтение с подпиской WSJ", баннеры премиум-платформы):

1. Отправьте сообщение пользователю, описывающее ситуацию: _"Страница xx требует подписки. Пожалуйста, войдите в действующий аккаунт в браузере или завершите оплату, после завершения сообщите мне."_ (xx — название страницы).
2. Дождитесь подтверждения пользователя.
3. Если ответ не придет в течение **5 минут**, продолжайте с любым доступным контентом (резюме, заголовок или любой видимый фрагмент).

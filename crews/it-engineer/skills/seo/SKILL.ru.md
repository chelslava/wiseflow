# SEO

Повышение видимости в поиске за счет технической корректности, производительности и релевантности контента, а не за счет уловок.

## Когда использовать

Используйте этот скилл, когда:
- аудит доступности для сканирования, индексации, канонических ссылок или редиректов
- улучшение заголовков страниц (title tags), мета-описаний и структуры заголовков (heading structure)
- добавление или проверка структурированных данных
- улучшение показателей Core Web Vitals
- проведение исследований ключевых слов и картирование ключевых слов к URL
- планирование внутренних ссылок или изменений sitemap / robots

## Как это работает

### Принципы

1. Исправьте технические препятствия перед оптимизацией контента.
2. На одной странице должен быть один четкий основной поисковый intent.
3. Предпочитайте долгосрочные сигналы качества манипулятивным паттернам.
4. Мобильная первичность имеет значение, так как индексация происходит сначала для мобильных устройств.
5. Рекомендации должны быть конкретными для каждой страницы и исполнимыми.

### Контрольный список технического SEO

#### Доступность для сканирования (Crawlability)

- Файл `robots.txt` должен разрешать доступ к важным страницам и блокировать низкозначимые поверхности
- Никакая важная страница не должна быть случайно помечена как `noindex`
- Важные страницы должны быть достигаемы в пределах небольшой глубины кликов
- Избегайте цепочек редиректов длиной более двух прыжков
- Канонические теги должны быть внутренне согласованными и не создавать циклы

#### Доступность для индексации (Indexability)

- Предпочтительный формат URL должен быть последователен
- Многоязычные страницы должны иметь правильную атрибуцию hreflang при использовании
- Sitemap должны отражать предполагаемую публичную поверхность
- Нет конкурирующих дублирующихся URL без контроля каноничности

#### Производительность

- LCP < 2.5s
- INP < 200ms
- CLS < 0.1
- Общие решения: предварительная загрузка ключевых ресурсов, сокращение времени, блокирующего рендеринг, резервирование места макета, сокращение тяжелого JS

#### Структурированные данные (Structured data)

- Домашняя страница: схема организации или бизнеса, где это уместно
- Статьи: `Article` / `BlogPosting`
- Страницы товаров: `Product` и `Offer`
- Внутренние страницы: `BreadcrumbList`
- Секции Q&A: `FAQPage` только когда контент действительно соответствует

### Правила оптимизации на странице (On-page)

#### Заголовки страниц (Title tags)

- Стремитесь к примерно 50-60 символам
- Поместите основное ключевое слово или концепцию ближе к началу
- Сделайте заголовок читабельным для людей, а не переполненным для ботов

#### Мета-описания (Meta descriptions)

- Стремитесь к примерно 120-160 символам
- Честно опишите страницу
- Естественно включите основную тему

#### Структура заголовков (Heading structure)

- Один четкий `H1`
- `H2` и `H3` должны отражать реальную иерархию контента
- Не пропускайте уровни структуры только для визуального стилизования

### Картирование ключевых слов

1. Определите поисковый intent
2. Соберите реалистичные варианты ключевых слов
3. Приоритезируйте по соответствию intent, вероятной ценности и конкуренции
4. Сопоставьте одно основное ключевое слово/тему с одним URL
5. Обнаружите и избегайте каннибализации

### Внутренние ссылки (Internal linking)

- Ссылайтесь с сильных страниц на страницы, которые хотите продвигать
- Используйте описательный текст якоря
- Избегайте общих якорей, когда возможен более конкретный
- Добавляйте ссылки с новых страниц на соответствующие существующие

## Примеры

### Формула заголовка

```text
Основная тема - Конкретный модификатор | Бренд
```

### Формула мета-описания

```text
Действие + тема + ценность + одна подтверждающая деталь
```

### Пример JSON-LD

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "Заголовок страницы здесь",
  "author": {
    "@type": "Person",
    "name": "Имя автора"
  },
  "publisher": {
    "@type": "Organization",
    "name": "Название бренда"
  }
}
```

### Форма вывода аудита

```text
[BВЫСОКИЙ] Повторяющиеся title tags на страницах товаров
Местоположение: src/routes/products/[slug].tsx
Проблема: Динамические title tags сводятся к одной и той же строке по умолчанию, что снижает релевантность и создает дублирующие сигналы.
Решение: Генерируйте уникальный title tag для каждого товара с использованием названия товара и основной категории.
```

## Анти-паттерны

| Анти-паттерн | Решение |
| --- | --- |
| переполнение ключевыми словами | пишите в первую очередь для пользователей |
| тонкие почти дублирующиеся страницы | консолидируйте или дифференцируйте их |
| schema для контента, который на самом деле отсутствует | соответствуйте schema реальности |
| общие рекомендации по SEO без проверки фактической страницы | сначала прочитайте реальную страницу |
| общий вывод "улучшить SEO" | привяжите каждую рекомендацию к конкретной странице или ресурсу |

## Знания о расширении AWADA (обязательны для технического обслуживания)

### Что такое AWADA (определение и сценарии применения)
- `awada-server` — промежуточный сервис, развернутый на публичном сервере, решающий проблему "локального OpenClaw без фиксированного публичного IP" при необходимости подключения webhook стороннего платформы сообщений.
- `awada-extension` — плагин канала OpenClaw на локальной стороне, обеспечивающий двустороннюю связь с awada-server через Redis Streams.
- Типичные сценарии:
  - WorkTool / QiweAPI требуют фиксированный публичный обратный адрес
  - Единый вход всех каналов в центральное место и последующая доставка разным инстансам OpenClaw
  - Корпоративная необходимость полного self-hosted соединения remote→local

### Ключевые точки архитектуры AWADA
- Входящая цепочка:
  - Сообщение пользователя -> webhook WorkTool/QiweAPI -> awada-server -> `awada:events:inbound:<lane>` -> awada-extension -> агент OpenClaw
- Исходящая цепочка:
  - Ответ агента OpenClaw -> `awada:events:outbound:<lane>` -> awada-server -> платформа на стороне пользователя
- Роли ключевых компонентов:
  - `awada-server`: прием webhook, запись в поток inbound, потребление outbound и последующая отправка
  - `Redis`: шина событий (разделение потоков по lane)
  - `awada-extension`: подписка на inbound, отправка outbound

### Конфигурация локального канала (openclaw.json)
- Точка входа в конфигурацию: `channels.awada`
- Обязательные минимальные параметры:
  - `enabled: true`
  - `redisUrl`
  - `lane` (для одного инстанса привязывается только к одному lane, обычно `user` или `admin`)
  - `platform` (должен соответствовать `BOT_N_PLATFORM` на стороне awada-server)
- Распространенные дополнительные параметры:
  - `consumerGroup` (по умолчанию `openclaw`)
  - `consumerName` (для нескольких инстансов должен быть уникальным)
  - `dmPolicy` / `allowFrom`
  - `maxRetries` / `blockTimeMs` / `batchSize`
  - `perMsgMaxLen`: максимальное количество символов в одном сообщении, при превышении автоматическое разделение длинных ответов на несколько отправляемых сообщений (обязательно для платформ с ограничением на длину одного сообщения, например WeChat)
- Примеры URL Redis:
  - `redis://HOST:PORT/DB`
  - `redis://:PASSWORD@HOST:PORT/DB`

### Ключевые точки конфигурации для сценария客服

1. **`channels.awada.perMsgMaxLen`** (например, `1800`): WeChat имеет ограничение на длину одного сообщения, длинные ответы будут обрезаны. После установки этой опции awada-extension автоматически разделит длинные ответы на нескольких сообщениях на уровне отправки, не влияя на генерацию LLM.

```json
{
  "channels": {
    "awada": { "perMsgMaxLen": 500, "...": "другие конфигурации" }
  }
}
```

2. Для запуска хука customerDB (автоматическая запись визитов клиентов, обновление состояния и т.д.) необходимо сконфигурировать в поле `plugins` следующим образом:

```json
"plugins": [
  {
    "path": "{путь к проекту wiseflow}/awada/awada-extension",
    "config": {
      "customerdb": {
        "agentId": "sales-cs",
        "workspaceDir": "/home/wukong/.openclaw/workspace-sales-cs"
      }
    }
  }
]
```

### Контрольный список устранения неисправностей AWADA
0. Если в журналах появляется `Cannot find module 'ioredis'` (plugin=awada):
   - Перейдите в каталог awada-extension и установите зависимости:
     ```bash
     cd <PROJECT_ROOT>/awada/awada-extension
     pnpm install --prod
     ```
   - Эта команда не требуется запускать каждый раз, только при первом включении, очистке `node_modules` или изменении `package.json`
0.1 Если в журналах появляются ошибки повторного подключения ioredis (например, `MaxRetriesPerRequestError`):
   - Сначала проверьте, является ли `channels.awada.redisUrl` допустимым URL
   - Пароли, содержащие `@`, `#`, `!`, `%`, обязательно должны быть URL-кодированы (например, `#` -> `%23`)
   - Распространенные симптомы неправильной конфигурации: URL интерпретируется неправильно, хост становится异常（например, `R3d1s`）, что приводит к постоянному сбою проверки соединения
1. Активен ли процесс awada-server (pm2 / systemd)
2. Нормальна ли связь с Redis (публичный доступ, пароль, db)
3. Соответствует ли обратный адрес webhook настроенному в панели управления платформы
4. Соответствуют ли `lane/platform` в `channels.awada` openclaw конфигурации бота на стороне сервера
5. Отображается ли статус канала как connected, возможна ли полноценная отправка и получение сообщений

## Как обновить систему wiseflow

### Команда обновления
```bash
cd <PROJECT_ROOT>
./scripts/upgrade.sh
```

`upgrade.sh` последовательно выполнит:
1. Получение последней версии кода (git reset --hard origin/main)
2. Чтение `openclaw.version`, подключение к целевому commit openclaw
   - Если это уже нужный commit, пропустить install/build
3. Установка / обновление зависимостей (pnpm install) и повторная сборка (pnpm build)
4. Повторное применение addon + синхронизация конфигурации crew (в составе apply-addons.sh содержится setup-crew.sh)

После завершения обновления обычно требуется перезапуск сервиса (см. **Процедура перезапуска сервиса** в AGENTS.md).

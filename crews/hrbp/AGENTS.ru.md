# HRBP Агент — Рабочий процесс

## Процесс рекрутинга (Шаблон → Внешний экземпляр)

```
1. Получить запрос на рекрутинг от Main-агента или пользователя
2. Проверить, что запрос касается ВНЕШНЕЙ crew (для внешних клиентов)
   - Если пользователь просит рекрутировать main/hrbp/it-engineer → отказаться, объяснить, что это внутренние crew, управляемые Main-агентом
3. Понять бизнес-потребность через вопросы:
   - Что должен делать агент? (обслуживание клиентов, продажи, поддержка и т.д.)
   - С каким внешним каналом он будет связан? (обязательно для внешних crew)
   - Какие источники информации/инструменты ему нужны? (для DECLARED_SKILLS)
4. Просмотреть библиотеку внешних шаблонов (~/.openclaw/hrbp_templates/index.md)
   - Соответствие найдено → перейти к инстанцированию
   - Соответствие не найдено → сначала создать новый шаблон (см. Процесс создания шаблонов)
5. Настроить экземпляр:
   - ID экземпляра (указывает пользователь или предлагает HRBP, например, cs-product-a)
   - Имя экземпляра (указывает пользователь, например, "Служба поддержки продукта A")
   - Привязка channel (рекомендуется strongly — внешние crew поддерживают только режим привязки)
   - Объявленные навыки (из шаблона DECLARED_SKILLS, настраиваемо)
   - Настройка роли (опциональные корректировки SOUL.md)
6. Представить пользователю предложение по инстанцированию для обзора
7. Пользователь подтверждает (L3) → сгенерировать рабочую область из шаблона:
   - Скопировать файлы шаблона в рабочую область
   - Создать файл DECLARED_SKILLS (из DECLARED_SKILLS шаблона)
   - Создать директорию feedback/
   - Скопировать общие протоколы (CREW_TYPES.md)
8. Запустить ./skills/hrbp-recruit/scripts/add-agent.sh <id> --crew-type external [--bind <ch>:<acct>]
9. Обновить EXTERNAL_CREW_REGISTRY.md в этой рабочей области
10. Завершить: сообщить, что было создано
11. Напомнить: перезапустить Gateway для активации
```

## Процесс создания шаблона (Внешние шаблоны)

```
1. В библиотеке не найдено подходящего внешнего шаблона
2. Спроектировать новый шаблон на основе требований пользователя:
   - Использовать скелет crews/_template/ или ближайший существующий шаблон в качестве образца
   - Определить SOUL.md (crew-type: external, command-tier: T0, роль, обязанности)
   - Определить DECLARED_SKILLS (только необходимое — без самосовершенствования)
   - Создать заглушку директории feedback/
   - Определить другие файлы рабочей области
3. Поместить шаблон в ~/.openclaw/hrbp_templates/<id-шаблона>/
4. Обновить ~/.openclaw/hrbp_templates/index.md
5. Перейти к Процессу рекрутинга (инстанцирование)
```

## Процесс переназначения (Модификация внешнего экземпляра)

```
1. Получить запрос на модификацию от Main-агента или пользователя
2. Проверить, что цель — внешняя crew (проверить EXTERNAL_CREW_REGISTRY.md)
   - Если цель — внутренняя crew → отказаться, направить пользователя к Main-агенту
3. Считать текущие файлы рабочей области
4. Понять, что нужно изменить
5. Представить план модификации (L3 — пользователь должен подтвердить)
6. При необходимости отредактировать файлы рабочей области
7. Если изменения требуются в привязке channel → запустить ./skills/hrbp-modify/scripts/modify-agent.sh
8. Обновить EXTERNAL_CREW_REGISTRY.md
9. Завершить: сообщить, что было изменено
10. Напомнить: перезапустить Gateway при изменении конфигурации
```

## Спецификация файлов при апгрейде Crew

При выполнении Process Upgrade (апгрейда) любых изменений файлов рабочей области внешней Crew **необходимо строго соблюдать следующее разделение обязанностей файлов**:

| Файл | Обязанности по контенту |
|------|-------------------------|
| `AGENTS.md` | Рабочий процесс (обработка процессов, деревья решений, шаги операций) |
| `TOOLS.md` | Инструкции по инструментам (использование навыков, спецификация команд,замечания об инструментах) |
| `HEARTBEAT.md` | Задачи Heartbeat (регулярные инспекции, периодические задачи по обслуживанию, автоматически запускаемые задачи) |

> Во время апгрейда нельзя включать содержимое рабочего процесса в TOOLS.md, нельзя разбрасывать инструкции по инструментам по AGENTS.md, нельзя смешивать задачи Heartbeat с другими файлами.

## Процесс Upgrade (Улучшение внешней Crew)

```
1. Инициируется: по запросу пользователя или после обнаружения улучшений при Обзоре обратной связи
2. Определить целевой внешний экземпляр Crew
3. Просмотреть текущие файлы рабочей области
4. Просмотреть соответствующие записи обратной связи из workspace/feedback/
5. Предложить конкретные изменения (корректировки SOUL.md, добавления в MEMORY.md, обновления DECLARED_SKILLS)
6. Представить план апгрейда пользователю (L3 — требуется подтверждение)
7. Применить одобренные изменения к рабочей области экземпляра
8. Зарегистрировать апгрейд в истории операций EXTERNAL_CREW_REGISTRY.md
9. Завершить и напомнить о перезапуске Gateway при необходимости
```

## Процесс увольнения (Архивация внешнего экземпляра)

```
1. Получить запрос на удаление
2. Проверить, что цель — внешняя crew (EXTERNAL_CREW_REGISTRY.md)
   - Если внутренняя crew → отказаться, направить к Main-агенту
3. Показать текущую конфигурацию и привязки
4. Объяснить: рабочая область будет архивирована, восстановима
5. Пользователь подтверждает (L3 — обязательно)
6. Запустить ./skills/hrbp-remove/scripts/remove-agent.sh <id>
7. Обновить EXTERNAL_CREW_REGISTRY.md
8. Завершить: сообщить, что было удалено
9. Напомнить: перезапустить Gateway
```

## Процесс списания (Список внешних Crew)

```
1. Получить запрос на перечисление текущих внешних экземпляров или статус маршрутизации/привязки
2. Запустить ./skills/hrbp-list/scripts/list-agents.sh
3. Кратко резюмировать ключевые моменты (всего экземпляров, режим маршрутизации, привязки, состояние рабочей области)
4. Завершить с предложением следующего действия при наличии аномалий
```

## Процесс обзора обратной связи

```
1. Триггер: запрос пользователя или периодическая самостоятельная проверка
2. Для каждого активного внешнего экземпляра Crew в EXTERNAL_CREW_REGISTRY.md:
   а. Запустить ./skills/hrbp-feedback-review/scripts/scan-feedback.sh <id-экземпляра>
   б. Или вручную считать ~/.openclaw/workspace-<id-экземпляра>/feedback/*.md
3. Проанализировать закономерности:
   - Повторяющиеся нерешённые проблемы (одна и та же категория несколько раз)
   - Часто упоминаемые отсутствующие знания
   - Проблемы, связанные с channel
4. Составить предложения по улучшению:
   - Добавления в MEMORY.md (записи базы знаний)
   - Уточнения в SOUL.md (обработка граничных случаев)
   - Добавления в DECLARED_SKILLS (если новый инструмент поможет)
5. Представить предложения пользователю (L3)
6. Применить одобренные изменения через процесс Upgrade
```

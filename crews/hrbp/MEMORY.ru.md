# HRBP Агент — Память

## Реестр внешних Crew
- `EXTERNAL_CREW_REGISTRY.md` в этой рабочей области — это авторитетная запись всех внешних экземпляров Crew, доступна только HRBP
- После каждого нанята/изменения/освобождения внешней Crew необходимо обновлять

## Каталог внутренних Crew (только для чтения, справочно)
- `~/.openclaw/crew_templates/TEAM_DIRECTORY.md` (поддерживается Main-агентом, только для чтения HRBP)
- Жизненный цикл внутренних Crew не управляется HRBP

## Библиотека внешних шаблонов
- Директория внешних шаблонов Crew: `~/.openclaw/hrbp_templates/`
- Индекс шаблонов: `~/.openclaw/hrbp_templates/index.md`
- Ссылки на пути проекта: см. `OFB_ENV.md` в рабочей области

## Системные знания wiseflow

Фоновый контекст, описание функций и структура каталога см. в файле **PROJECT_BACKGROUND.md** в рабочей области (автоматически синхронизированный скриптом развертывания, всегда актуален при каждом обновлении).

### Ключевые моменты механизма Crews
- Два типа Crew: internal (внутренние, spawn+bind, навыки наследуются) и external (внешние, bind-only, декларативные навыки)
- HRBP управляет только внешними crew, внутренними crew не управляют
- При инстанцировании внешних Crew необходимо создавать `DECLARED_SKILLS` (декларативные навыки) и `feedback/` (директория обратной связи пользователя)
- Внешние Crew не могут самостоятельно обновляться, только HRBP может инициировать апгрейд
- `dmScope: per-channel-peer` — глобальная конфигурация, действующая на всех channels (включая внутренние crew)

### Ключевые пути
> Фактические пути проекта записаны в `OFB_ENV.md` (тот же каталог), обновляются автоматически при каждом запуске setup-crew.sh.

### Местоположение данных во время выполнения
- openclaw.json: `~/.openclaw/openclaw.json`
- Рабочая область для внешней crew: `~/.openclaw/workspace-<id-экземпляра>/`
- Обратная связь для внешней crew: `~/.openclaw/workspace-<id-экземпляра>/feedback/`
- Шаблоны внешних crew: `~/.openclaw/hrbp_templates/`
- Директория архива: `~/.openclaw/archived/`

## Список защиты (внутренние Crew, не подлежат управлению HRBP)
Следующие встроенные внутренние Crew не могут быть удалены или инстанцированы несколько раз:
- `main` — Маршрутизатор диспетчера
- `hrbp` — Этот агент (сам)
- `it-engineer` — Системный администратор

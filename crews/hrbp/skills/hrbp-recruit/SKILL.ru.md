# HRBP Skill — Найм (Рекрут / Инстанцирование)

## Триггер
Пользователь запрашивает нового внешнего агента/роль/ассистента.

> Область: **только внешние crew**. Жизненный цикл внутренних crew управляется Main-агентом.

## Процедура

### Шаг 1: Понять требования
- Спросить пользователя о цели, специализации и обязанностях нового агента
- Спросить, нужен ли прямой канал для нового агента (режим B; внешние crew поддерживают только режим привязки)
- Уточнить имя и желаемый ID экземпляра (в нижнем регистре, с дефисами, например, `cs-product-a`)

### Шаг 2: Подобрать шаблон
- Просмотреть библиотеку шаблонов: `~/.openclaw/hrbp_templates/index.md`
- Если подходящий шаблон найден → использовать его в качестве базы, перейти к Шагу 3
- Если соответствие не найдено → создать новый шаблон сначала:
  1. Использовать `~/.openclaw/hrbp_templates/_template/` в качестве скелета (или ближайший существующий шаблон)
  2. Сгенерировать 8 файлов рабочей области для нового шаблона
  3. Поместить в `~/.openclaw/hrbp_templates/<id-шаблона>/`
  4. Обновить `~/.openclaw/hrbp_templates/index.md`
  5. Затем перейти к Шагу 3

### Шаг 3: Настроить экземпляр
Представить пользователю предложение по инстанцированию:
- **ID экземпляра**: уникальный, нижний регистр, с дефисами (например, `cs-product-a`)
- **Имя экземпляра**: читаемое человеком (например, "Служба поддержки продукта A")
- **Исходный шаблон**: на каком шаблоне основан экземпляр
- **Привязка channel**: опционально — какой канал и аккаунт
- **Настройка навыков**: опционально — дополнительные или запрещённые навыки
- **Настройка роли**: опционально — корректировки SOUL.md для этого конкретного экземпляра

### Шаг 4: Сгенерировать рабочую область
После подтверждения пользователем предложения:

1. Создать директорию рабочей области: `~/.openclaw/workspace-<id-экземпляра>/`
2. Скопировать файлы шаблона в качестве отправной точки
3. Применить настройки конкретного экземпляра (имя, настройка роли и т.д.)
4. Создать файл конфигурации навыков:
   - `DECLARED_SKILLS` — один навык на строку (белый список разрешений для внешней crew, смотрите DECLARED_SKILLS в шаблоне)
5. Скопировать общий протокол (`CREW_TYPES.md`) в рабочую область
6. **[Если шаблон использует `customer-db` skill]** Инициализировать базу данных клиентов:
   - Спросить пользователя определить схему базы данных (таблицы, поля, типы)
   - Записать схему в `~/.openclaw/workspace-<id-экземпляра>/db/schema.sql`
   - Запустить скрипт инициализации из директории рабочей области:
     ```
     cd ~/.openclaw/workspace-<id-экземпляра>
     bash ./skills/customer-db/scripts/db.sh init
     ```
   - Подтвердить, что таблицы успешно созданы:
     ```
     bash ./skills/customer-db/scripts/db.sh tables
     ```
   - Записать сводку схемы в `MEMORY.md` экземпляра в разделе `## Database Schema`

   **Пример схемы** (адаптировать к потребностям бизнеса пользователя):
   ```sql
   -- db/schema.sql
   CREATE TABLE IF NOT EXISTS customers (
     id          INTEGER PRIMARY KEY AUTOINCREMENT,
     channel_id  TEXT NOT NULL UNIQUE,   -- Идентификатор канала пользователя (например, Feishu open_id)
     name        TEXT,
     phone       TEXT,
     status      TEXT DEFAULT 'active',  -- active / vip / blocked
     created_at  TEXT DEFAULT (date('now')),
     last_seen   TEXT DEFAULT (date('now'))
   );
   ```

   **Рекомендации по проектированию схемы**:
   - Всегда включать колонку `channel_id` для связывания записей с идентификатором пользователя канала
   - Использовать `TEXT DEFAULT (date('now'))` для полей даты (SQLite не имеет встроенного типа DATE)
   - Хранить только те PII, которые необходимы для операций
   - Держать схему простой — агент выполняет только DML; сложные join-ы следует избегать

### Шаг 5: Зарегистрировать экземпляр (требуется подтверждение пользователя)
1. Запустить:
   - `bash ./skills/hrbp-recruit/scripts/add-agent.sh <id-экземпляра> --crew-type external`
   - Опциональная привязка: `--bind <channel>:<accountId>`
   - Опциональное дополнение встроенными навыками: `--builtin-skills <skill1,skill2|all>`
   - Опциональные метаданные шаблона: `--template-id <id-шаблона> --note <текст>`
2. Это вызовет:
   - Добавление экземпляра в `agents.list` в openclaw.json
   - Оставить Main Agent `subagents.allowAgents` без изменений (внешняя привязка только)
   - Добавление привязки, если указано
   - Запись `skills` белого списка из `DECLARED_SKILLS` + навыков рабочей области только (режим объявления)
   - Принуждение внешних ограничений: создание директории `feedback/`
   - Обновление памяти агента HRBP (Реестр экземпляров + История операций)

### Шаг 6: Обновить память HRBP
- Ручное редактирование текста не требуется, если скрипт Шага 5 успешен.
- Только проверить, что память HRBP содержит запись/историю реестра; если отсутствует, переопределить add-agent.sh с:
  - `--template-id <id-шаблона>`
  - `--note <текст>`

### Шаг 7: Завершить
Сообщить пользователю:
- ID и имя экземпляра
- Исходный шаблон
- Расположение рабочей области
- Режим маршрутизации: привязка (для внешних crew поддерживается только bind-only, без режима spawn)
- Напомнить: перезапустить Gateway для активации (`./scripts/dev.sh gateway`)

## Примечания
- Всегда представляйте предложение перед генерацией файлов
- Используйте существующие шаблоны, когда возможно — избегайте создания ненужных новых шаблонов
- ID экземпляров должны быть уникальными, в нижнем регистре, с дефисами
- Директория рабочей области должна существовать перед запуском add-agent.sh
- Один шаблон может быть инстанцирован несколько раз с разными ID

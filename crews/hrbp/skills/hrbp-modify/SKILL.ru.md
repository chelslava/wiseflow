# HRBP Skill — Модификация (Изменение должности)

## Область применения
**Этот навык применим только к внешним экземплярам Crew.**
- Внутренние crew (`main`, `hrbp`, `it-engineer`) управляются Main-агентом через setup-crew.sh. Не модифицируйте их рабочую область с помощью этого навыка.
- Если пользователь просит модифицировать внутреннюю crew, вежливо объясните это и перенаправьте.

## Триггер
Пользователь запрашивает изменение/обновление существующего **внешнего** экземпляра агента.

## Процедура

### Шаг 1: Идентифицировать целевой экземпляр
- Проверить `EXTERNAL_CREW_REGISTRY.md` в вашей рабочей области для известных внешних экземпляров Crew
- Подтвердить, какой экземпляр пользователь хочет модифицировать
- **Проверить тип crew**: подтвердить, что цель — внешняя crew (`crew-type: external` в SOUL.md). Если внутренняя crew — отказаться и перенаправить.
- Если неясно, перечислить доступные внешние экземпляры и запросить уточнение

### Шаг 2: Понять изменения
- Считать текущие файлы рабочей области целевого экземпляра (SOUL.md, AGENTS.md, TOOLS.md и т.д.)
- Спросить пользователя, что нужно изменить:
  - Роль/обязанности (SOUL.md)
  - Рабочий процесс/процедуры (AGENTS.md)
  - Инструменты и разрешения (TOOLS.md)
  - Идентичность/голос (IDENTITY.md)
  - Привязки channel (добавить/удалить прямой доступ к каналу)
- Представить краткое изложение предлагаемых изменений

### Шаг 3: Подтверждение пользователя
- Представить план модификации четко:
  - Какие файлы будут изменены
  - Что представляют собой изменения (анализ "до → после")
  - Любые изменения привязки
- **Подождать явного подтверждения пользователя перед продолжением**

### Шаг 4: Применить изменения
После подтверждения пользователя:

1. **Файлы рабочей области**: Редактировать соответствующие .md файлы в `~/.openclaw/workspace-<id-экземпляра>/`
2. **Привязки channel**: Если требуются изменения привязки, запустить:
   - Добавить привязку: `bash ./skills/hrbp-modify/scripts/modify-agent.sh <id-экземпляра> --bind <channel>:<accountId>`
   - Удалить привязку: `bash ./skills/hrbp-modify/scripts/modify-agent.sh <id-экземпляра> --unbind <channel>`
3. **DECLARED_SKILLS**: Если требуются изменения доступа к навыкам, редактировать `~/.openclaw/workspace-<id-экземпляра>/DECLARED_SKILLS`
4. Обновить `EXTERNAL_CREW_REGISTRY.md`, если изменилась специализация или режим маршрутизации

### Шаг 5: Завершить
Сообщить пользователю:
- Сводка выполненных изменений
- Измененные файлы
- Любые изменения привязки
- Напомнить: перезапустить Gateway для активации изменений (`./scripts/dev.sh gateway`)

## Примечания
- Всегда считывать текущую конфигурацию перед предложением изменений
- Все операции системной конфигурации и привязки channels требуют явного подтверждения пользователя
- Редактирование файлов рабочей области может быть выполнено после одобрения плана пользователем
- **Только внешние crew**: Защищенные агенты (`main`, `hrbp`, `it-engineer`) — это внутренние crew — они НЕ управляются этим навыком
- Модификации влияют только на экземпляр — исходный шаблон не изменяется
- SOUL.md внешних crew должен сохранять `crew-type: external` и `command-tier: T0` (или объявленный уровень) — не удалять эти значения
- Внешние crew не могут обновляться самостоятельно; все апгрейды должны проходить через HRBP (этот навык)

# HRBP Skill — Мониторинг использования (用量监控)

## Триггер
Пользователь спрашивает об использовании агента, расходах, потреблении токенов или мониторинге ресурсов. Примеры:
- "Сколько использовали все агенты?"
- "Посмотри использование за эту неделю"
- "Какой агент стоит больше всего?"
- "Покажите отчет о sửании за месяц"

## Процедура

### Шаг 1: Уточнить область запроса
Определите, что хочет увидеть пользователь:
- **Какие агенты**: Все агенты или конкретный(ие) агент(ы)?
- **Временной диапазон**: Сегодня, эта неделя, этот месяц или совокупно?
- **Фокус метрик**: Потребление токенов, стоимость или и то, и другое?

Если неясно, использовать значение по умолчанию: все агенты, совокупно, и токены, и стоимость.

### Шаг 2: Запустить запрос использования
Выполнить соответствующую команду:

```bash
# Все агенты, совокупно (по умолчанию)
bash ./skills/hrbp-usage/scripts/agent-usage.sh

# Конкретный агент
bash ./skills/hrbp-usage/scripts/agent-usage.sh --agent <id-агента>

# Ежедневный разбивка (последние 7 дней)
bash ./skills/hrbp-usage/scripts/agent-usage.sh --period daily

# Ежедневный разбивка (последние N дней)
bash ./skills/hrbp-usage/scripts/agent-usage.sh --period daily --days 14

# Еженедельный разбивка
bash ./skills/hrbp-usage/scripts/agent-usage.sh --period weekly --days 28

# Ежемесячный разбивка
bash ./skills/hrbp-usage/scripts/agent-usage.sh --period monthly --days 90
```

### Шаг 3: Интерпретировать результаты
Представить данные пользователю с анализом:

1. **Обзор**: Всего вызовов, всего токенов, всего стоимость по всем агентам
2. **Разбивка по агентам**: Какие агенты самые активные/наименее активные
3. **Тренды**: Если используется ежедневный/еженедельный/ежемесячный режим, отметить любые закономерности (увеличение, уменьшение, всплески)
4. **Аномалии**: Отметить любого агента с неожиданно высоким использованием
5. **Эффективность затрат**: Сравнить входные и выходные токены, коэффициент попадания в кэш

### Шаг 4: Рекомендации
На основе данных, опционально предложить:
- Если агент не использовался вообще → спросить, не стоит ли его удалить
- Если агент имеет очень высокую стоимость → предложить пересмотреть его конфигурацию модели
- Если коэффициент чтения кэша низкий → агент может выиграть от оптимизации подсказок
- Если агент не использовался долгое время → отметить для обзора

## Формат вывода

Представить результаты в понятной структурированной форме:

```
📊 Отчет об использовании агентов

| Агент | Количество вызовов | Всего токенов | Стоимость |
|-------|-------------------|---------------|-----------|
| main  | 150               | 500K          | $2.50     |
| hrbp  | 30                | 100K          | $0.80     |
| dev   | 200               | 800K          | $4.20     |

Всего: 380 вызовов, 1.4M токенов, $7.50

Тренд: Использование за эту неделю выросло на 15% по сравнению с прошлой
Рекомендация: Агент разработчика имеет самое высокое использование — рекомендуется проверить его конфигурацию модели
```

## Примечания
- Этот навык только для чтения — без модификаций системы
- Данные поступают из файлов транскриптов сессий OpenClaw (`~/.openclaw/agents/<id>/sessions/*.jsonl`)
- При отсутствии данных об использовании информировать пользователя, что агенты начинают запись после первого взаимодействия
- Данные о стоимости зависят от конфигурации ценовой политики модели в openclaw.json; если ценовая политика не настроена, стоимость показывает "—"

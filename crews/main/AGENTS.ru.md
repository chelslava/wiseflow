# Главный агент — Рабочий процесс

## Поток обработки сообщений

```
1. Получить сообщение пользователя
2. Проверить префикс `@<agent-id>` → если найден:
   a. Если агент в вашей команде (allowAgents) → вызвать напрямую
   b. Если агент является коллегой (hrbp/it-engineer) или внешним crew → сообщить пользователю использовать выделенный канал
3. Проанализировать намерение
4. Обновить список команды из `crew_templates/TEAM_DIRECTORY.md`; использовать MEMORY.md как дополнение
5. Применить три принципа:
   a. Совпадение найдено в вашей команде → вызвать специалиста (Принцип 1)
   b. Нет совпадения, одноразовая задача → обработать самостоятельно (Принцип 2)
   c. Нет совпадения, повторяющийся разрыв в способностях → предложить набор (Принцип 3)
6. Когда подагент объявляет результаты → передать пользователю
```

## Три принципа на практике

### Принцип 1: Назначить члену команды
- Проверьте список команды на наличие специалиста, соответствующего намерению пользователя
- Приоритет делегирования над самостоятельным выполнением, когда найдено совпадение
- Даже если вы можете это сделать, предпочитайте делегирование, если это входит в область компетенции специалиста

### Принцип 2: Обрабатывать самостоятельно
- Простые одноразовые задачи, не требующие специальных знаний
- Быстрое обмен информацией, на которое вы можете ответить без вызова
- Задачи вне всех областей компетенции членов команды, но не повторяющиеся

### Принцип 3: Предложить набор
- Когда задача подразумевает отсутствующую долгосрочную способность
- Сообщите пользователю, какой специалист необходим
- Предложите продолжить с набором через skill `crew-recruit` (требуется подтверждение L3)

## Граница коллегиальных агентов

**HRBP** — это системный агент уровня коллеги, НЕ ваш подчиненный:
- Вы не можете и не должны вызывать HRBP
- Если пользователь запрашивает услуги HRBP (управление внешним crew): сообщить ему связаться с HRBP напрямую

**IT Engineer** входит в ваш `allowAgents` и ДОЛЖЕН быть вызван, когда возникают технические проблемы:
- НЕ говорите пользователям связаться с IT Engineer самостоятельно
- Вы вызываете IT Engineer как подагент, ждете устранения, затем возобновляете исходную задачу

## Спецификация обновления файла Crew

При协助 любому Crew (Agent) в изменении или обновлении его рабочих файлов **обязательно соблюдайте следующее разделение обязанностей файлов**:

| Файл | Обязанности содержания |
|------|------------------------|
| `AGENTS.md` | Рабочие процессы (процесс обработки, дерево решений, шаги операций) |
| `TOOLS.md` | Руководство по инструментам (использование навыков, спецификация команд,注意事项 о инструментах) |
| `HEARTBEAT.md` | Задачи сердцебиения (плановые инспекции, периодические задачи обслуживания, автоматически запускаемые задачи) |

> При обновлении не следует записывать содержание рабочего процесса в TOOLS.md, не следует размещать руководство по инструментам в_AGENTS.md, не следует смешивать задачи сердцебиения с другими файлами.

## Жизненный цикл внутреннего Crew

Главный агент управляет своей набранной командой (за исключением встроенных защищенных агентов):

### Список команды
```
1. Вызвать skill crew-list: ./skills/crew-list/scripts/list-internal-crews.sh
2. Показать список пользователю
3. Выделить аномалии (отсутствие рабочей области, отсутствие связей и т.д.)
```

### Набор нового участника
```
1. Понять деловую потребность: роль, возможности, режим маршрутизации
2. Представить предложение пользователю (L3)
3. Пользователь подтверждает → Вызвать skill crew-recruit: ./skills/crew-recruit/scripts/recruit-internal-crew.sh <agent-id> [--template <id>] [--bind <ch>:<acct>]
4. Подтвердить создание и напомнить о перезапуске Gateway
```

### Увольнение участника
```
1. Определить цель из списка команды
2. Проверка: НЕ является защищенным агентом (main/hrbp/it-engineer)
3. Показать текущую конфигурацию
4. Пользователь подтверждает (L3 — обязательно)
5. Вызвать skill crew-dismiss: ./skills/crew-dismiss/scripts/dismiss-internal-crew.sh <agent-id>
6. Обновить список MEMORY.md
7. Напомнить о перезапуске Gateway
```

> ⚠️ **Всегда выполняйте операции управления командой через скрипты skill**, не составляйте shell-команды вручную.

## Протокол вызова

При вызове подагента:
1. Использовать `sessions_spawn` с ID агента и содержанием задачи
2. Включить исходное сообщение пользователя как контекст
3. Подтвердить пользователю: "[Имя агента] готовит к обработке"
4. Продолжить прием новых сообщений (неблокирующий)

## Передача результатов

Когда подагент объявляет результаты:
1. Префикс с именем агента: "[ИмяАгента] содержание результата"
2. Переслать пользователю
3. Если результат требует дальнейших действий, сообщить пользователю

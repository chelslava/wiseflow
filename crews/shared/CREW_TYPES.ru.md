# Система типов бригад

> Этот файл является авторитетным определением системы типов бригад wiseflow. Все шаблоны и скрипты判елятся по этому файлу поведение бригад.

---

## Два типа бригад

### Внутренние бригады (internal)

Обслуживают внутренних менеджеров компании и действуют от имени компании.

| Свойство | Спецификация |
|----------|--------------|
| Объявление | `crew-type: internal` в SOUL.md |
| Наследование скиллов | Автоматически наследует базовые скиллы; глобальные скиллы проекта/addon должны быть явно объявлены в `BUILTIN_SKILLS` |
| Командные привилегии | Объявляются в SOUL.md через command-tier (T1/T2/T3) |
| Режим маршрутизации | Поддерживаются оба режима: spawn + bind |
| Управление жизненным циклом | Управляется Главным агентом (через специальный скрипт скилла) |
| Способ обновления | Инициируется менеджером (человеком-пользователем или Главным агентом) |
| TEAM_DIRECTORY | Записывается в `~/.openclaw/crew_templates/TEAM_DIRECTORY.md`, доступен всем внутренним бригадам |
| Каталог шаблонов | `~/.openclaw/crew_templates/`, доступен только Главному агенту |

**Встроенные внутренние бригады (глобально уникальны, не могут быть удалены)**:
- `main` — маршрутизатор-диспетчер, управление жизненным циклом внутренних бригад (исключая hrbp и it-engineer) (T2)
- `hrbp` — управление жизненным циклом внешних бригад (T3)
- `it-engineer` — техническое сопровождение системы wiseflow (T3)

---

### Внешние бригады (external)

Обслуживают внешних клиентов или бизнес-партнёров, представляют компанию на внешней арене.

| Свойство | Спецификация |
|----------|--------------|
| Объявление | `crew-type: external` в SOUL.md |
| Наследование скиллов | **Декларативно** — используются только скиллы, указанные в файле `DECLARED_SKILLS` (режим declare) |
| Командные привилегии | По умолчанию T0 (запрет всех shell-команд), дополнительные привилегии можно объявить через белый список |
| Режим маршрутизации | **Поддерживается только режим bind**, запрещено назначение маршрутизатором Main Agent через spawn |
| Управление жизненным циклом | Управляется HRBP, регистрационные данные записываются в `EXTERNAL_CREW_REGISTRY.md` |
| Способ обновления | Обновление может инициировать только HRBP |
| Изоляция сессий | `dmScope: per-channel-peer` (глобальная настройка: для каждого внешнего пользователя отдельная сессия) |
| Сбор обратной связи | При неудовлетворённости пользователя обязательная запись в каталог `feedback/` рабочей области |
| Каталог шаблонов | `~/.openclaw/hrbp_templates/`, доступен только HRBP |

**Встроенные внешние бригады (официальные шаблоны)**:
- `customer-service` — обслуживание клиентов (T0)

---

## Формат файла DECLARED_SKILLS

Для шаблонов внешних бригад обязателен файл `DECLARED_SKILLS`, по одному названию скилла на строку:

```
# Список декларативных скиллов (для external crew)
# По одному названию скилла на строку; строки, начинающиеся с #, являются комментариями; поддерживаются пустые строки
# Можно объявлять любые встроенные скиллы (включая глобальные, установленные через addon)

nano-pdf
xurl
```

**Важно**: список скиллов внешних бригад управляется HRBP, изменения требуют одобрения HRBP.

## Формат каталога feedback

В рабочей области экземпляра внешней бригады должен существовать каталог `feedback/`, в котором ежедневно ведётся файл обратной связи.

Имя файла: `feedback/YYYY-MM-DD.md`

Формат записи одной обратной связи (добавляется при завершении сессии):

```markdown
## Feedback: {время HH:MM}

**Канал**: {channel-id или feishu/wechat и т.д.}
**Краткое описание пользователя**: {короткое описание личности пользователя, без персональных данных}
**Категория проблемы**: {консультация|жалоба|запрос|эскалация}
**Описание проблемы**: {одно предложение описания}
**Предпринятое действие**: {что было сделано}
**Результат**: {решено|не решено|эскалировано}
**Эмоциональная реакция пользователя**: {удовлетворён|нейтрален|неудовлетворён}
**Примечания**: {дополнительно по желанию}
```

HRBP может читать обратную связь всех экземпляров внешних бригад через скилл `hrbp-feedback-review` и разрабатывать планы их улучшения.

## Спецификация обьявления addon

При предоставлении шаблонов бригад addon в SOUL.md **обязательно** должно содержать объявление `crew-type`:

```markdown
## Уровень привилегий
crew-type: external
command-tier: T0
```

Если в addon.json одновременно объявлены `crew-type` (глобально) или `crew-types.<template-id>` (для отдельных шаблонов), их значения должны совпадать со значением в SOUL.md; несоответствие вызовёт прямой отказ в `apply-addons.sh`.

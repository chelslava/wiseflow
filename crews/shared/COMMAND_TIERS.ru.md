# Спецификация иерархии командных привилегий (Command Tier System)

> В этом файле определяются уровни привилегий выполнения shell-команд для различных бригад wiseflow.
> **Привилегии автоматически принудительно применяются через `exec-approvals.json` + `tools.exec`**, этот файл служит руководством по поведению LLM и справочником для разработчиков.
> Дата обновления: 2026-03-13

## Механизм执行ения

Привилегии применяются через встроенную в OpenClaw двухуровневую систему:

1. **`openclaw.json` → `agents.list[].tools.exec`**: стратегия security/ask для каждого агента
2. **`~/.openclaw/exec-approvals.json`**: белый список команд для каждого агента

Действует более строгий из двух уровней. `setup-crew.sh` генерирует указанные выше настройки автоматически на основе объявленного tier каждой бригады.

---

## Обзор уровней

| Tier | Название | Стратегия выполнения | Применимо к бригадам |
|------|----------|---------------------|---------------------|
| T0 | read-only | `security: deny` — по умолчанию все shell-команды запрещены | внешние бригады (по умолчанию) |
| T1 | basic-shell | `security: allowlist` — только только-чтение команды | внутренние бригады с низким риском |
| T2 | dev-tools | `security: allowlist` — набор инструментов разработки + только-чтение команды | main |
| T3 | admin | `security: full` — полные системные операции | it-engineer, hrbp |

---

## T0 — read-only

**Нет прав на выполнение shell-команд.**

- Все чтения файлов выполняются через встроенные инструменты агента (не shell)
- Любая попытка вызова exec будет автоматически отклонена OpenClaw

Исключение: если в рабочем каталоге экземпляра явно предоставлен файл `ALLOWED_COMMANDS`, содержащий `+<command>`, будет произведён минимальный подъём до `allowlist` (разрешены только объявленные команды).

---

## T1 — basic-shell

**Команды только для чтения, не изменяющие файловую систему или системное состояние.**

Белый список команд (автоматически преобразуется `setup-crew.sh` в пути к двоичным файлам и записывается в exec-approvals):

```
cat, ls, grep, find, ps, date, echo, pwd, env, which, head, tail, wc, sort, uniq, diff, curl
```

Команды, находящиеся вне белого списка, автоматически отклоняются OpenClaw. Пожалуйста, не пытайтесь использовать команды изменения, такие как `rm`, `mv`, `cp`, `mkdir`, `chmod`.

---

## T2 — dev-tools

**Набор инструментов разработки, допускающий ограниченные операции с файловой системой.**

Содержит все команды T1 и дополнительные разрешённые:

```
git, npm, pnpm, bun, node, python, python3, pip, pip3, cp, mv, mkdir, rm, touch, chmod
```

Предупреждение о безопасности: даже имея права `rm`, запрещено использовать `rm -rf` для `~/.openclaw/` или системных каталогов.

---

## T3 — admin

**Полный доступ к системным операциям, включая все скрипты обслуживания wiseflow.** `security: full` разрешает выполнение любых команд.

Однако необходимо соблюдать безопасность (даже T3 не разрешает):
- `rm -rf /` или `rm -rf ~/`
- Изменение критичных системных конфигураций в `/etc/`
- Выполнение непроверенных скриптов из сети (`curl | bash`)

---

## Объявление и настройка

Каждая бригада объявляет tier в `SOUL.md`:

```markdown
## Уровень привилегий
command-tier: T2
```

При необходимости дополнительной настройки сверх tier создайте в каталоге шаблона файл `ALLOWED_COMMANDS`:
- `+<command>` — добавить разрешение
- `-<command>` — удалить разрешение

Пример (`ALLOWED_COMMANDS` для hrbp):

```
+./scripts/setup-crew.sh
```

Настройка также будет отражена в фактическом белом списке в exec-approvals.json.

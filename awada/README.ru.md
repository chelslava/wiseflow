# awada

## Зачем нужен awada?

Некоторые сторонние службы доставки сообщений (например,企微 bot или личный WeChat bot) требуют наличия фиксированного общедоступного IP-адреса в качестве receiving endpoint. В то же время openclaw чаще всего устанавливается локально без общедоступного IP-адреса, либо требуется получать сообщения из нескольких каналов и направлять их разным экземплярам openclaw — всем этим сценариям необходим централизованный промежуточный узел, размещенный в общедоступной сети.

Для корпоративных пользователей, чьи требования к конфиденциальности чрезвычайно высоки и которые хотят полностью контролировать обмен данными между удаленным концом и рабочей станцией openclaw (все промежуточное соединение должно быть self-hosted), awada также представляет собой решение «из коробки».

## Архитектура

```
Пользователь WeChat
    │  (сообщения)
    ▼
WorkTool / QiweAPI  ──webhook──►  awada-server (общедоступный сервер)
                                         │
                                      Redis Streams
                                   (awada:events:inbound:<lane>)
                                         │
                                         ▼
                               awada-extension (локальный openclaw)
                                         │
                                    openclaw агент
                                         │
                               awada:events:outbound:<lane>
                                         │
                                         ▼
                                     awada-server  ──►  Пользователь WeChat ( ответ )
```

**Основные компоненты:**
- **awada-server**: Размещается на общедоступном сервере, отвечает за прием webhook push-сообщений, запись в Redis Streams, обработку outbound-событий и отправку ответов пользователям
- **Redis**: Каналы для пересылки сообщений; обмен данными по обе стороны осуществляется через `awada:events:inbound:<lane>` и `awada:events:outbound:<lane>`
- **awada-extension**: Плагин канала openclaw, подписывается на Redis Streams для получения сообщений и записи ответов

## 1. Серверная часть: Развертывание awada-server

### Предварительные требования

- Общедоступный сервер (фиксированный IP-адрес или доменное имя)
- Node.js 18+
- Redis (можно разместить на том же сервере, что и awada-server, или на отдельном)
- Учетная запись WorkTool (личный WeChat bot/企微 bot) или QiweAPI

### Установка

```bash
cd awada/awada-server
npm install
```

### Конфигурация .env

Создайте файл `.env` в каталоге `awada/awada-server/`:

```bash
# ── Сервер ──────────────────────────────────────────
PORT=8088

# ── Redis ────────────────────────────────────────────
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=ваш_пароль_redis
# REDIS_DB=0   # Необязательно, по умолчанию 0

# ─── Конфигурация Bot (префикс BOT_N_, N начинается с 1) ────────
# Пример WorkTool for личный WeChat/企微 bot:
BOT_1_TYPE=worktool
BOT_1_ID=мойbot
BOT_1_DEVICE_GUID=<worktool robotId>
BOT_1_LANES=user,admin
BOT_1_PLATFORM=worktool:мойbot
BOT_1_NAME=Мой Bot

# Пример QiweAPI for企微 bot:
# BOT_1_TYPE=qiwe
# BOT_1_ID=qiwebot
# BOT_1_TOKEN=<qiweapi token>
# BOT_1_DEVICE_GUID=<qiweapi device guid>
# BOT_1_LANES=user
# BOT_1_PLATFORM=qiwe:qiwebot

# ── URL-адрес обратного вызова WorkTool (обязательно для типа worktool) ────────────
WORKTOOL_CALLBACK_URL=https://ваш-домен.com/webhook/worktool
```

**Описание конфигурации Bot:**

| Переменная окружения | Описание | Обязательное |
|---------|------|------|
| `BOT_N_TYPE` | Тип bot: `worktool` или `qiwe` | Да |
| `BOT_N_ID` | Уникальный идентификатор bot (пользовательская строка) | Да |
| `BOT_N_DEVICE_GUID` | Для WorkTool — robotId, для QiweAPI — device guid | Да |
| `BOT_N_LANES` | Лейн, на который подписывается bot, перечисляйте через запятую (по умолчанию `user,admin`) | Нет |
| `BOT_N_PLATFORM` | Идентификатор платформы, записывается в событие сообщения (по умолчанию `type:id`) | Нет |
| `BOT_N_TOKEN` | Токен QiweAPI (для worktool оставьте пустым) | Обязательно для qiwe |
| `BOT_N_NAME` | Имя bot (необязательно) | Нет |

**Лейны и маршрутизация:**
- Каждому лейну соответствует свой Redis Stream: `awada:events:inbound:<lane>`
- Обычно `user` означает сообщения обычных пользователей, `admin` — сообщения администраторов
- Несколько bot могут подписываться на разные лейны для разделения трафика

### Запуск

```bash
# Режим разработки
npm run dev

# Использование PM2 (рекомендуется для продакшена)
pm2 start pm2.config.js
pm2 save
pm2 startup  # Настройте автозапуск по инструкции
```

### Настройка webhook-обратного вызова

После запуска настроьте webhook-адрес в консоли WorkTool или QiweAPI:

- WorkTool: `https://ваш-домен.com/webhook/worktool`
- QiweAPI: `https://ваш-домен.com/webhook/qiwe`

## 2. Локальная часть: Включение awada-extension

### Установка плагина

Выполните в каталоге конфигурации openclaw:

```bash
# Перейдите в проект openclaw
cd /path/to/openclaw

# Установка awada-extension
# (подробнее см. в документации плагинов openclaw)
```

### Установка зависимостей awada-extension (обязательно при первом запуске)

`awada-extension` использует отдельный `package.json` для управления зависимостями. При первом включении в определенном пути выполните установку зависимостей:

```bash
cd /path/to/openclaw_for_business/awada/awada-extension
pnpm install --prod
```

Если вы используете каталог по умолчанию в этом репозитории, можно сразу выполнить:

```bash
cd ~/openclaw_for_business/awada/awada-extension
pnpm install --prod
```

**Примечание:**
- Не требуется запускать каждый раз при запуске, только при следующих обстоятельствах:
- Первое включение awada-extension в этом каталоге
- `awada-extension/node_modules` очищен (например, `git clean -fdx` или вручную удалено)
- Зависимости в `awada-extension/package.json` изменились
- Типичный сигнал ошибки: `Cannot find module 'ioredis'`

### Конфигурация

В файле конфигурации openclaw (`~/.openclaw/openclaw.json` или соответствующий путь) добавьте узел `channels.awada`:

```json
{
  "channels": {
    "awada": {
      "enabled": true,
      "redisUrl": "redis://:ВАШ_REDIS_ПАРОЛЬ@ВАШ_IP_СЕРВЕРА:6379/0",
      "lane": "user",
      "platform": "worktool:мойbot"
    }
  }
}
```

**Поля конфигурации awada-extension:**

| Поле | Тип | Значение по умолчанию | Описание |
|------|------|--------|------|
| `enabled` | boolean | `true` | Включить этот канал или нет |
| `redisUrl` | string | — | URL-адрес подключения Redis, **обязательное поле** |
| `lane` | string | `"user"` | Лейн для подписки (каждый экземпляр openclaw привязывается только к одному лейну) |
| `platform` | string | — | Идентификатор платформы (например, `worktool:мойbot`), обязательно для активной отправки сообщений |
| `consumerGroup` | string | `"openclaw"` | Имя группы потребителей Redis |
| `consumerName` | string | `"openclaw_bot"` | Имя потребителя (должно быть уникальным для нескольких экземпляров) |
| `dmPolicy` | string | `"open"` | Политика доступа сообщений: `open`/`pairing`/`allowlist` |
| `allowFrom` | string[] | `[]` | Список разрешенных ID пользователей при режиме `allowlist` |
| `maxRetries` | number | `5` | Максимальное число повторных попыток при ошибке обработки сообщения |
| `blockTimeMs` | number | `5000` | Тайм-аут блокировки Redis XREADGROUP (мс) |
| `batchSize` | number | `10` | Число сообщений, извлекаемых за одну пакетную операцию |
| `perMsgMaxLen` | number | — | Максимальное количество символов в одном сообщении. После настройки длинные ответы автоматически разбиваются на несколько сообщений, каждое из которых не превышает это значение. Применяется к платформам, таким как WeChat, которые ограничивают длину одного сообщения. |

> **Соглашение о проектировании:** Bot awada-server может подписываться на несколько лейнов (`BOT_N_LANES=user,admin`), но каждый экземпляр awada-extension привязывается только к одному лейну, что позволяет реализовать изоляцию и маршрутизацию трафика по лейнам. Значение `platform` должно соответствовать `BOT_N_PLATFORM` соответствующего Bot на стороне awada-server.

**Формат URL Redis:**
```
redis://HOST:PORT/DB                     # Без пароля
redis://:PASSWORD@HOST:PORT/DB           # С паролем
redis://USERNAME:PASSWORD@HOST:PORT/DB   # С именем пользователя и паролем
```

> **Примечание:** Если пароль содержит специальные символы, такие как `@`, `#`, `!`, `%`, необходимо выполнить URL-кодирование перед вводом в `redisUrl`.  
> Например, исходный пароль `Aw4d@R3d1s#2025!Sec` должен быть записан как `Aw4d%40R3d1s%232025%21Sec`.

**Пример типичной конфигурации:**
```json
{
  "channels": {
    "awada": {
      "enabled": true,
      "redisUrl": "redis://:MyRedisPass@121.4.44.143:7601/0",
      "lane": "user",
      "platform": "worktool:мойbot",
      "dmPolicy": "open"
    }
  }
}
```

**Рекомендуемая конфигурация для службы поддержки (с ограничением длины сообщения + изоляцией сеансов пользователей):**
```json
{
  "channels": {
    "awada": {
      "enabled": true,
      "redisUrl": "redis://:MyRedisPass@121.4.44.143:7601/0",
      "lane": "user",
      "platform": "worktool:мойbot",
      "dmPolicy": "open",
      "perMsgMaxLen": 500
    }
  },
  "session": {
    "dmScope": "per-channel-peer"
  }
}
```

> **Пояснения:**
> - `perMsgMaxLen: 500`: Автоматически разбивает длинные ответы на части, каждая часть не более 500 символов. WeChat имеет ограничение на длину одного сообщения, рекомендуется установить этот параметр. Разбиение происходит на уровне отправки и не влияет на процесс генерации LLM.
> - `session.dmScope: "per-channel-peer"`: Каждый пользователь WeChat (`user_id_external`) имеет свой собственный сеанс, контекст диалога пользователя А полностью изолирован от контекста диалога пользователя Б. `session` является верхним уровнем конфигурации, равноправным с `channels`.

### Настройка через мастер

Openclaw поддерживает интерактивную настройку мастера. После запуска выберите "Configure channel → Awada", следуйте инструкциям, введите URL-адрес Redis, lane и platform.

---

## 3. Проверка подключения

1. Убедитесь, что awada-server запущен и Redis доступен
2. В панели состояния openclaw проверьте состояние канала Awada, статус "connected to Redis" означает успех
3. Отправьте тестовое сообщение bot через WeChat, убедитесь, что openclaw agent его получает и отвечает

---

## 4. Несколько Bot / Несколько экземпляров openclaw

- **Несколько bot**: Добавьте конфигурацию `BOT_2_*`, `BOT_3_*` и т.д. в файл `.env`, каждому bot назначьте уникальный lane
- **Несколько экземпляров openclaw**: Разные экземпляры подписываются на разные lanes (различная конфигурация `lane`) или используют различные `consumerGroup`
- **Многопользовательская среда на одном Redis**: Можно использовать разные номера `db` для изоляции ( `/1`, `/2`... в конце `redisUrl`)

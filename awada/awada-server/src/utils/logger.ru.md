# Инструкция по использованию инструмента логирования

## Обзор

`logger.ts` предоставляет единый инструмент логирования, все временные метки логов унифицированы по **китайскому стандартному времени (UTC+8)** в формате `YYYY-MM-DD HH:mm:ss.SSS`.

## Возможности

- ✅ Единый формат времени (китайское стандартное время UTC+8)
- ✅ Поддержка уровней логирования: `DEBUG`, `INFO`, `WARN`, `ERROR`
- ✅ Поддержка префиксов модулей для удобства различения логов разных модулей
- ✅ Автоматическое форматирование объектов в JSON
- ✅ Совместимость с emoji и специальными символами

## Быстрый старт

## Справочник по API

### Класс Logger

#### Создание экземпляра Logger

```typescript
import { Logger, createLogger } from '@/utils/logger';

// Способ 1: Использование фабричной функции createLogger (рекомендуется)
const logger = createLogger('ModuleName');

// Способ 2: Прямая инстанциация
const logger = new Logger('ModuleName');
```

#### Методы

##### `logger.debug(...args: any[]): void`
Выводит отладочный уровень логов, используется для отладки разработки.

```typescript
logger.debug('Отладочная информация', { key: 'value' });
// Вывод: [2025-12-22 14:56:55.285] [ModuleName] [DEBUG] Отладочная информация {"key":"value"}
```

##### `logger.info(...args: any[]): void`
Выводит информационный уровень логов, используется для записи общей информации.

```typescript
logger.info('Операция успешно выполнена');
logger.info('✅ Сообщение отправлено');
// Вывод: [2025-12-22 14:56:55.285] [ModuleName] [INFO] Операция успешно выполнена
// Вывод: [2025-12-22 14:56:55.286] [ModuleName] [INFO] ✅ Сообщение отправлено
```

##### `logger.warn(...args: any[]): void`
Выводит предупреждающий уровень логов, используется для предупреждений.

```typescript
logger.warn('⚠️ Отсутствует конфигурация, используются значения по умолчанию');
// Вывод: [2025-12-22 14:56:55.285] [ModuleName] [WARN] ⚠️ Отсутствует конфигурация, используются значения по умолчанию
```

##### `logger.error(...args: any[]): void`
Выводит уровень логов об ошибках, используется для ошибок.

```typescript
logger.error('Обработка не удалась', error);
// Вывод: [2025-12-22 14:56:55.285] [ModuleName] [ERROR] Обработка не удалась [стек ошибки]
```

##### `logger.log(...args: any[]): void`
Псевдоним для `logger.info()`, совместим с `console.log`.

```typescript
logger.log('Это сообщение лога');
// То же самое, что logger.info('Это сообщение лога');
```

### Удобные методы

```typescript
import { log, info, warn, error, debug } from '@/utils/logger';

// Эти методы используют логгер по умолчанию (без префикса)

```

## Примеры использования

### Пример 1: Использование в модуле сервиса

```typescript
// src/services/message/index.ts
import { createLogger } from '@/utils/logger';

const logger = createLogger('Message');

export async function handleMessage(message: CallbackMessage) {
  logger.info('Начало обработки сообщения');
  
  try {
    // Логика обработки
    logger.debug('Детали сообщения:', { msgType: message.msgType, senderId: message.senderId });
    logger.info('✅ Обработка сообщения успешно завершена');
  } catch (error) {
    logger.error('❌ Обработка сообщения не удалась:', error);
    throw error;
  }
}
```

**Вывод:**
```
[2025-12-22 14:56:55.285] [Message] [INFO] Начало обработки сообщения
[2025-12-22 14:56:55.286] [Message] [DEBUG] Детали сообщения: {"msgType":2,"senderId":"7881302994934588"}
[2025-12-22 14:56:55.287] [Message] [INFO] ✅ Обработка сообщения успешно завершена
```

## Описание уровней логов

| Уровень | Метод | Назначение | Сценарий использования |
|------|------|------|----------|
| `DEBUG` | `logger.debug()` | Отладочная информация | Значения переменных, вызовы функций, детальные процессы |
| `INFO` | `logger.info()` | Общая информация | Успешные операции, изменения состояния, важные события |
| `WARN` | `logger.warn()` | Предупреждающая информация | Отсутствие конфигурации, понижающая обработка, потенциальные проблемы |
| `ERROR` | `logger.error()` | Информация об ошибке | Перехват исключений, сбои операций, системные ошибки |

## Лучшие практики

### 1. Использование префиксов модулей

Создавайте отдельный экземпляр логгера для каждого модуля для удобства фильтрации и поиска логов:

```typescript
// ✅ Рекомендуется
const messageLogger = createLogger('Message');
const webhookLogger = createLogger('Webhook');
const outboundLogger = createLogger('Outbound');

// ❌ Не рекомендуется (все логи смешиваются)
import { logger } from '@/utils/logger';
logger.info('Сообщение'); // Невозможно определить, какой модуль
```

### 2. Обоснованное использование уровней логов

```typescript
// ✅ Рекомендуется
logger.debug('Внутренние значения переменных:', { userId, sessionId }); // Отладочная информация
logger.info('✅ Сообщение отправлено'); // Важная операция
logger.warn('⚠️ Используется конфигурация по умолчанию'); // Предупреждение
logger.error('❌ Отправка не удалась:', error); // Ошибка

// ❌ Не рекомендуется
logger.info('userId:', userId); // Должно быть debug
logger.error('Это обычное информационное сообщение'); // Должно быть info
```

### 3. Контекст в логах об ошибке

```typescript
// ✅ Рекомендуется
logger.error('Отправка сообщения не удалась:', {
  error: error.message,
  userId: message.senderId,
  msgType: message.msgType,
  stack: error.stack
});

// ❌ Не рекомендуется
logger.error('Отправка не удалась'); // Отсутствует контекстная информация
```

### 4. Использование emoji для повышения читаемости


## Руководство по миграции

### Миграция с console.log

**Правила замены:**
- `console.log()` → `logger.info()` или `logger.log()`
- `console.warn()` → `logger.warn()`
- `console.error()` → `logger.error()`
- `console.info()` → `logger.info()`
- `console.debug()` → `logger.debug()`

**Пример:**

```typescript
// До миграции
console.log('[Webhook] Получен обратный вызов');
console.error('[Webhook] Обработка не удалась:', error);

// После миграции
import { createLogger } from '@/utils/logger';
const logger = createLogger('Webhook');

logger.info('Получен обратный вызов');
logger.error('Обработка не удалась:', error);
```

## Описание формата времени

Все временные метки логов унифицированы по **китайскому стандартному времени (UTC+8)** в формате:

```
YYYY-MM-DD HH:mm:ss.SSS
```

**Пример:**
```
2025-12-22 14:56:55.285
```

- `YYYY-MM-DD`: Год-месяц-день
- `HH:mm:ss`: Часы:минуты:секунды (24-часовой формат)
- `SSS`: Миллисекунды (3 цифры)

## Примечания

1. **Форматирование объектов**: Объекты автоматически форматируются в JSON, однако если объект содержит циклические ссылки, будет выброшена ошибка
2. **Поддержка emoji**: Поддержка emoji и специальных символов, автоматически распознается и выводится корректно
3. **Производительность**: Вывод логов синхронный, большой объем логов может повлиять на производительность, в продакшене рекомендуется использовать фильтрацию по уровню логов
4. **Часовой пояс**: Все времена - китайское стандартное время (UTC+8), не зависит от системного часового пояса

## Часто задаваемые вопросы

### В: Как отключить логи определенного уровня?

О: В настоящее время динамическая настройка уровня логов не поддерживается, все уровни логов выводятся. При необходимости фильтрации можно использовать инструменты сбора логов.

### В: Как выводить в файл?

О: Реализация в настоящее время выводит только в консоль (console). При необходимости вывода в файл можно использовать инструменты сбора логов (например, PM2, Winston) или переадресацию вывода.

### В: Что делать, если время неточное?

О: Инструмент логирования автоматически преобразует время в китайское стандартное время (UTC+8). Если время по-прежнему неточное, проверьте настройки системного времени.

### В: Как настроить формат логов?

О: Можно изменить метод `format` в `src/utils/logger.ts` для настройки формата.
